# MidiSea 資料導演台 — IXD2026

**繁體中文** ｜ [English](./README.en.md)

線上版：<https://midisea.shyetech.com>　·　IxDA Taiwan 2026 會員工作坊「AI 共生黑客鬆」　·　12 組 卡加布列島（英文產品名：MidiSea Data Director）

用 **KORG nanoKONTROL2 / nanoPAD2** 兩台 MIDI 控制器（也可以用滑鼠、觸控、手機遙控、手把、相機手勢或語音），即時「演奏」一顆**化為海洋的 3D 星球**——透明球殼裡的療癒深海，內含水母、魚群、鯨豚、海龜與海洋垃圾，並有一片逐漸轉化成文字與數字的海。海況由台灣**政府開放資料**（水利署、中央氣象署；經 [Twinkle Hub](https://hub.twinkleai.tw/zh-TW) 探索資料集）驅動；另有一個「空氣品質」選項用的是 Open-Meteo 的 CAMS **模型資料**（不是政府觀測值，畫面上都會標示）；自己申請環境部金鑰後，還能把環境部測站觀測與模型並列比較（沒有金鑰時完全不影響現況，見〈資料 / 授權〉）。參數可 MIDI Learn 綁定、可錄製回放、可分享、可錄影下載；介面有**繁體中文 / English** 兩個語系。第一次進站有一步一步的互動新手導覽；講解者可以用**手機當導覽員遙控器**（也能用語音或揮手換站）；整天不關機的展場有自動復原的防呆；換到新裝置前可以用內建的**裝置診斷頁**逐項確認硬體。

> 核心命題：把抽象的多維資料，變成一台可以用雙手演奏的資料樂器。

## 快速開始

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 單元測試 + i18n 驗收（node --test）
npm run i18n       # 只跑 i18n 報告：未包 t() 的中文、缺英文的 key
npm run build      # 產生 dist/
```

用**桌面版 Chrome / Edge** 開啟 http://localhost:5173，按「連線 MIDI」允許權限。

> Web MIDI 需要 Chrome / Edge + localhost 或 HTTPS；Safari（macOS 與 iOS）沒有 Web MIDI，Firefox 需另外授權且未驗證，詳見〈瀏覽器 / 裝置支援矩陣〉。內建瀏覽器沙盒會擋 MIDI 權限——實體裝置請用你自己的 Chrome。沒有硬體時，頂部「控制器」可用滑鼠鍵盤操作虛擬 nanoKONTROL2；iPad / iPhone 請用「多人」掃 QR 當遙控器。
>
> 相機（AR 實景、相機手勢）、麥克風（語音指令）與雙螢幕自動放置都需要 **HTTPS 或 localhost**。
>
> 要到現場、或換到一台沒用過的裝置之前，先開 `?diagnostics=1`（「裝置」面板也有連結）跑一次**裝置診斷頁**，逐項確認相機、麥克風、語音、震動、螢幕等能不能用，見〈裝置診斷頁〉。

## 主要功能

| 功能 | 說明 |
|---|---|
| 3D 海洋球 | Three.js / R3F；透明球殼 + 程序化波浪 + 海洋生物 + 流動文字；**滑鼠拖曳 / 旋鈕改變旋轉** |
| 中英雙語 | 頂部語言鈕（顯示 `EN` / `中文`）一鍵切換整站介面、日誌、資料名稱與分享文案；`?lang=en` / `?lang=zh` 可用網址指定。見〈語系〉 |
| 參數面板 | 分組滑桿，每個參數可 **MIDI Learn** 綁定 CC |
| 錄製 / 播放 | 把整段旋鈕演出錄下並回放；**soft-takeover** 播放中抓旋鈕平順接管、不跳值 |
| 分享 | 產生帶「資料脈絡」的網址：`?s=…`（視覺參數）＋ `&o=`（海況）`&m=`（月份）`&sl=`（鳥魚連動）`&lang=`（語系）；舊版只有 `?s=` 的連結照常可開。見〈分享〉 |
| 分享星球 | 擷取此刻的海合成分享卡（帶目前資料列）→ 手機系統分享 / 桌機下載 PNG，並附文案「我在 MidiSea 演了一片海 [網址]」（網址就是同一條帶脈絡的分享連結）。**實景（AR）時連相機拍到的真實背景一起輸出**：以 `object-fit: cover` 的幾何把相機畫面對位到畫布、套用與畫面相同的背景模糊 / 清澈濾鏡，再疊上透明的 WebGL 畫布（舊版 Safari 沒有 `ctx.filter` 時以縮放近似模糊）；「錄影」同理逐幀合成 |
| 資料導覽 | 按 **`T`**、資料卡的「▶ 開始導覽」，或閒置 30 秒：依序巡演八站（今日水庫 → 花蓮潮汐 → 月亮 → 雲林揚塵 → **空氣品質（模型資料）** → 鳥群 → 魚群 → 河川測站星座；也可以用**導覽腳本**自訂要講哪幾站、什麼順序），畫布下方大字幕用當下的真實資料說明「現在看的是什麼、球為什麼長這樣」，並誠實點出資料限制；預設整輪約 111 秒，碰任何東西就停並還原。**導覽員控制**：進度點可點跳站、上一站 / 下一站 / 暫停（鍵盤 `←` `→` `P`）、「複製此站連結」（`?tourstop=`）、選用的語音旁白；也可以**語音說「下一站」、對相機揮手**換站。見〈資料導覽〉 |
| 導覽員手機遙控 | 「多人」視窗切到「導覽員」分頁（演出模式或展場按 **`G`**，顯示 60 秒）出現專屬 QR，講解者用手機掃碼：上一站 / 暫停 / 下一站大按鈕、開始 / 結束導覽、站別跳轉、該站備註、這一站的剩餘秒數與下一站預告、念出字幕開關，站在投影機旁就能講解。**只能操控導覽、不能演奏**；驗證用的 token 只在這次開啟的主畫面有效。手機鎖屏 / 切到背景後會自動重連，並在連線期間要求螢幕保持喚醒（**真機的實際行為尚未驗證**）。見〈多人合奏與導覽員遙控〉 |
| 導覽腳本 | 面板「資料導覽」卡片的「導覽腳本」：勾選要講的站、排順序、每站寫一段備註（最多 120 字，顯示在字幕下方、開旁白時會被念出），最多存 5 份，「複製腳本連結」產生像 `?tour=air,fish` 的網址給別人開。備註只存在這台瀏覽器或連結裡，不上傳。見〈資料導覽〉 |
| 新手導覽 | 第一次進站出現 7 步互動導覽（半透明遮罩 + 聚光框 + 提示卡，每步一兩句話），取代過去一進站就跳出的長篇說明。完整說明仍在「說明」鈕後面，重整成「快速上手 5 條 + 6 個預設收合的主題區塊 + 海洋生態區塊」，並可按「重新看新手導覽」。`?onboard=0` / `?onboard=1` 可關 / 強制顯示。見〈新手導覽、系統事件監看與視角取景〉 |
| 系統事件監看可隱藏 | 畫面下方的「輸入輸出監看（IN 演奏者 / OUT 系統事件）」可用標題列的小箭頭、Footer 的「系統事件」開關或鍵盤 **`L`** 隱藏；桌面預設顯示、手機預設隱藏，切換後記住。隱藏時 Footer 仍用一行小字顯示最新一則 OUT 事件，日誌照常累積。`?log=1` / `?log=0` 只覆寫這一次 |
| 視角自動取景 | 畫布窄長（例如手機直式全螢幕的演出模式）時，相機自動拉遠讓整顆球看得到；橫式、桌面與接近正方形的畫布維持原本取景、完全不變。有兩種取景可選（「裝置 → 取景」或 `?fit=full` / `?fit=fill`）：**完整**（預設，含光暈）與**填滿**（球殼填滿手機直式的寬度，球更大、光暈被邊緣裁掉一部分）；手機直式時測站星座也會避開頂端的資料列。縮放滑桿與雙指縮放照常可用；`?fit=0` 關閉 |
| 裝置診斷頁 | `?diagnostics=1`（「裝置」面板有連結）：25 項一鍵快速檢查 + 15 項按鈕才啟動的互動檢查（旁白、看門狗、相機手勢、相機、麥克風、語音、MIDI、手把、震動、觸控筆、感測器、螢幕、彈出視窗、全螢幕），可複製 / 下載報告；**導引模式**（`?diagnostics=1&guided=1`）一次一項帶你做完互動檢查，並可填選用的**裝置備註**；不上傳任何東西。見〈裝置診斷頁〉 |
| 展場防呆 | 畫面出錯時倒數自動重新載入（5 → 15 → 60 秒退避，10 分鐘內 5 次熔斷停手，之後**約 10 分半鐘再自動試一次**）、WebGL 遺失復原、渲染看門狗、新版與新資料自動更新（閒置時才動；手機遙控器 3 分鐘內有操作也算有人在）、`?reload=HH` 每日重載；畫面右下角的 **8px 維運指示燈**（`?kiosk` 預設顯示）用形狀與顏色顯示目前狀態；「裝置 → 維運」可看版本、崩潰紀錄與啟用的防呆。見〈展場防呆與維運〉 |
| 點物件看資料出處 | 輕點背景上的測站星 / 月亮 / 球外鳥群，在物件旁彈出資料卡（來源、數值、狀態）。見〈點物件看資料出處與觸控筆〉 |
| 觸控筆 | 用 Apple Pencil / Surface Pen / Wacom 拖曳球體：壓力放大浪勁、筆身傾斜推動洋流方向（僅 `pointerType === 'pen'`；`?pen=0` 關閉） |
| 多人合奏 | 按「多人」秀 QR，手機掃碼變遙控器（PeerJS WebRTC，短 ID → QR 小而好掃）；每支手機分到「聲部」（海 / 生態 / 氛圍 / 自由）、滑桿每秒跟主畫面同步；**手機感測器**：啟用後傾斜=洋流方向、搖晃=浪湧（走同一條 wire 協定）。全部走同一條 `input()` 路徑（可錄製、可 soft-takeover）。host 與訊號伺服器斷線會用同一 ID 自動重連、被銷毀則換號重建；手機端鎖屏 / 切背景後也會自動重連。另有「導覽員」分頁的專屬 QR（見上一列與〈多人合奏與導覽員遙控〉） |
| 「裝置」面板 | 頂部「裝置」鈕：把選用的裝置功能集中一處——**觀眾視窗（雙螢幕）**、**相機手勢**（張手 / 捏合，導覽中揮手換站）、**語音指令**（含導覽員指令「下一站」等）、**取景**（完整 / 填滿）、**觸覺回饋**、**畫質**，以及**裝置診斷**（診斷頁與導引模式連結、上次結果）、**維運**（版本、崩潰紀錄、防呆狀態、指示燈開關）兩節；相機 / 麥克風只在你打開時才啟用，畫面與聲音都不上傳。見〈「裝置」面板〉 |
| 真實資料 | 水庫水位 % **直接等於海水高度**（滿庫=滿球，>97% 液體從球外緣溢流、球底積水痕）；石門 / 德基 / 曾文附 24h 進流量、**花蓮外海附 CWA 潮汐**時間序列，可「▶ 播放資料」讓球隨真實資料起伏（**倍速 ×0.5–×4、循環**，畫布上方 HUD 顯示資料時刻與數值）；另有「**揚塵 · 雲林縣**」「**月亮 · 花蓮**」「**空氣品質 · 雲林**」三個海況，全部資料集見下方〈資料集 → 畫面〉 |
| 空氣品質（模型資料 + 選用的環境部觀測） | 「空氣品質 · 雲林」海況：Open-Meteo Air Quality API（CAMS 全球大氣模型）在雲林縣麥寮的逐時 PM2.5、PM10 與 US AQI。**這是模型資料，不是政府觀測值**（資料卡的琥珀色標籤、資料看板、OUT 日誌都標示「模型資料」；資料卡另有一行可見的說明：約數十公里的粗網格模型估計，可能與地面測站數值不同，請勿當官方空品判讀）。「▶ 播放空氣品質 120 小時」以每小時 0.2 秒回放最近 5 天：PM2.5 越高，海水越混濁、垃圾越多、色相偏黃綠、輝光收斂。資料卡與資料看板有 120 小時的**迷你折線圖**（播放時標出目前那一小時）。**有環境部金鑰時**（要自己申請，步驟見〈資料 / 授權〉），管線會多抓離模型格點最近的環境部測站，資料卡多一張「**模型 vs 觀測**」小卡（兩條線加一句描述性結論）與「驅動海況的資料」切換（有觀測時預設用觀測），資料看板多「觀測 / 落差 / 驅動」三列；驅動來源解析為觀測時，**靜態海況**（換選項、「套用此海況」、首次到訪、分享連結、導覽還原）也用觀測的最新 PM2.5，與看板「映射」列一致；你選的驅動來源只存在記憶體（重新整理回到自動），頁面定期的就地資料更新不會把它洗掉；**沒有金鑰時完全不影響現況**。CC BY 4.0，需標示 Open-Meteo（資料卡有連結）。見〈資料集 → 畫面〉 |
| 銀河 × 河川 | 背景帶狀銀河，濃度由**水利署即時河川水位**（5 站 / 警戒比）驅動——水豐則銀河更亮 |
| 鳥群 / 魚群 × 調查資料 | 球外線稿鳥群數 =「鳥群數量」參數（0..1 → 0..5 群）；魚群同理走「魚群數量」。資料卡顯示該流域**逐月物種數長條圖**（斜線＝內插、點長條預覽月份、標示現在），並給資料建議值，你可以「**套用資料**」、開「**連動**」（換海況 / 換月份時自動更新），或直接拖曳滑桿「**獨立控制**」（手動調會自動脫鉤，參數列的「資料」標籤消失）。每個流域另有**調查年表**（時間軸）可「▶ 播放」：每一步＝一個日曆年，數量隨當年物種數變化，沒有調查的年份標為「無調查」並以前後調查年內插補上。注意（資料誠實聲明）：各流域僅部分月份 / 年度有調查（每月只涵蓋 1–3 個年度，近似單一年份快照，非氣候平均），只收紀錄數達門檻的月份，缺月以相鄰月份**環狀內插**並標註「內插」。見〈調查空窗時間軸〉 |
| 月亮 × 潮汐 | 潮汐海況時背景出現月亮：**盈虧＝當日月齡（由 CWA 農曆日期推得，與潮汐資料同源）**、位置＝月中天時刻與當下時刻決定的天空弧線（新月正午 / 上弦傍晚 / 滿月午夜中天）。資料播放 24h 潮位時月亮真的東升西落，HUD 同步顯示乾/滿潮標記、農曆、潮差、月相。另有獨立海況「**月亮 · 花蓮**」：以 CWA A-B0063-001 的月出 / 中天 / 月沒時刻、月出月沒**方位角**與中天**仰角**把月亮放在真實的方位與高度（閒置＝今天 × 現在時刻內插；「▶ 播放月出月沒」每一步＝一天，月亮每晚 21:00 的位置與盈虧逐日推進，中天越高海水越高＝示意） |
| 資料看板 · 輸出顯示資料 | 畫布左上「資料看板」列出目前海況背後的真實資料與映射（水庫 / 潮汐 / 揚塵 / 空氣品質 / 氣象 / 鳥 / 魚 / 河川 / 測站，手機預設關）；**OUT 監看**在套用海況時輸出「資料 …」列、資料播放**每一步**輸出「DATA …」行；「分享星球」圖片也帶資料列（播放中的空氣品質序列用哪個來源，圖上的列就照實說，與資料看板同一個判斷）；匯出 LOG 一併包含 |
| 畫面資訊面板控制 | 畫布上的資訊面板分三組、各自可關：**資料看板** / **播放與參數提示**（資料播放進度、參數數值、待接管旋鈕提示、AR 調整鈕、聲音提示、導覽字幕、資料出處卡片）/ **掃碼 QR 與統計**（演出模式）。頂部「**資訊**」鈕或鍵盤 **`I`** 一鍵全部隱藏 / 顯示（再按一次還原原本的組合）；看板右上 **×**；資料卡「畫面顯示」三個勾選分別開關；偏好存 localStorage。網址覆寫 `?hud=0`（看板+提示）/ `?board=0` / `?qr=0`（給展場、錄影用，不會蓋掉使用者偏好）。隱藏的面板直接卸載（不空跑動畫迴圈）。相機手勢與語音的「使用中」徽章是隱私提示，**不受此開關控制、永遠顯示** |

## 控制對應（nanoKONTROL2 出廠預設）

**6 推桿 (Slider 1–6, CC0–5)**

| 推桿 | 效果 |
|---|---|
| 1 | 海水高度 |
| 2 | 洋流速度 |
| 3 | 水母數量 |
| 4 | 魚群數量 |
| 5 | 垃圾數量 |
| 6 | 海水清澈程度 |

**2 旋鈕 (Knob 1–2, CC16–17)**：旋轉海洋球 / 生物游動速度。

**4 按鈕 (Button 1–4, Solo CC32–35)**：鯨魚出現 / 海豚出現 / 海龜出現 / 清除垃圾。

**走帶鍵**：● 錄製開始/結束、▶ 播放/停止、■ 停止、Cycle 清除錄製——演出全程不碰滑鼠。

**LED 回饋**（nanoKONTROL2 需以 KORG Kontrol Editor 設 LED Mode = External）：錄製中 ● 閃、播放中 ▶ 亮、待播放 ■ 亮、Learn 模式 Cycle 閃、soft-takeover 待接管時該軌 R 鍵閃、觸發鍵按下亮 0.3 秒。

**藍牙 MIDI（Web Bluetooth）**：「藍牙 MIDI」鈕直接以 GATT 連 BLE-MIDI 控制器 / 鍵盤（不必先在系統配對），與 USB 共用同一條 `routeMidi` 路徑，Learn / 錄製 / soft-takeover 通用。支援 Chrome / Edge（桌面、Android）；**iPad / iPhone 的 Safari（與其他 iOS 瀏覽器）沒有 Web Bluetooth，也沒有 Web MIDI**——那些裝置請用「多人」掃 QR 當遙控器（WebRTC，不需藍牙）。

**nanoPAD2 X-Y 觸控板**：X（Pitch Bend）→ 洋流向 X（攪動浪的方向）；Y 預設不綁（點「洋流向 Y」→ 滑觸控板即 Learn）。

**nanoPAD2 打擊墊：16 效果 × 4 bank（=64 墊）**：`note % 16` 選效果、`note ÷ 16` 選強度檔位（弱 / 中 / 強 / 爆，對應 nanoPAD2 Scene 或音高區段），velocity＝力度。效果表：水母脈衝 / 浪湧 / 漣漪 / 氣泡 / 亮星 / 海豚 / 鯨魚 / 海龜 / **淨化波** / 垃圾投放 / 洋流轉向 / 閃光 / 魚群衝刺 / 漣漪三連 / 星雨 / 大浪+氣泡。虛擬控制器有相同的 16 墊 + bank 切換。

**手機觸控／感測**：左右拖曳=旋轉（放手有慣性）、上下滑=海水高度、兩指縮放=遠近、點擊=亮星爆發、**長按 0.5 秒=魚群聚集到手指**、**傾斜手機=水面保持水平**、**搖晃=攪動海水**（iOS 首次觸碰會請求感測權限）。可「加入主畫面」以 PWA 全螢幕離線使用。

> **生態連動**：垃圾增加 → 海水混濁、生物減少、**魚群主動繞開垃圾**、點綴音轉小調；清除垃圾 → **淨化波**擴散、生物回歸、聲音回到大調。背景另有 4 分鐘一輪的極慢晝夜。
> 若你的裝置 CC 不同：**點參數名稱 → 轉旋鈕**即重綁（Learn），或按「依序對應旋鈕」；`shift+點` 解綁。按鈕也可用畫面上的動作鈕（滑鼠 / 觸控）。綁定存 localStorage。

| 參數 | 值 | 作用 | 備註 |
|---|---|---|---|
| `?s=` | base64url | 視覺參數（每個參數量化成 1 byte，依 `PARAM_ORDER` 順序） | 「分享」產生；位置編碼不能改，舊連結靠它解碼 |

| `?qr=0` | `0` | 隱藏展場 QR 與統計 | 同上 |

| `?diagnostics=1` | `1`（`0` `false` `off` `no` 為關） | 裝置診斷頁（獨立頁面，不載入 3D 場景與主畫面） | 「裝置」面板的「開啟裝置診斷」會開新分頁；頁面路由優先序：手機遙控頁 `#remote=` > 診斷頁 > 觀眾視窗 > 主畫面。見〈裝置診斷頁〉 |
| `&guided=1` | `1`（`0` `false` `off` `no` 為關） | 配合 `?diagnostics=1`：載入後自動跑快速檢查並直接進入導引模式 | 沒有 `?diagnostics=1` 時沒有作用；「裝置」面板的「開啟導引模式」連結就是這個網址 |
| `?log=` | `1` `0`（也認 `true` `on` `yes` `show`、`false` `off` `no` `hide`） | 這一次強制顯示 / 隱藏輸入輸出監看（系統事件） | 不寫入偏好；優先序：網址 > 使用者偏好 > 依寬度預設（>820px 顯示、≤820px 隱藏） |
| `?onboard=` | `1` `0`（`0` `false` `off` `no` 為關，其餘算開） | 強制顯示 / 不顯示新手導覽 | `?onboard=1` 蓋過「已看過」與 `?kiosk`；手機遙控頁、觀眾視窗、診斷頁一律沒有新手導覽（連 `?onboard=1` 也不行）；`?kiosk` 與 `?tourstop=` 預設不顯示 |
| `?fit=` | `full`（或 `1`）· `fill` · `0`（`false` `off` `no` 同） | `full` / `fill`：這一次用「完整」或「填滿」取景；`0`：關閉視角自動取景（除錯用） | 只覆寫這一次、不寫偏好；優先序：網址 > 「裝置 → 取景」的偏好 > 預設（完整）；寬螢幕兩種取景本來就沒有差別。其他值視為沒指定（`?fit=on` 不會蓋掉偏好） |
| `?oplight=` | `1` `0`（`false` `off` `no` 同 `0`；沒有值視為開） | 這一次強制顯示 / 隱藏右下角的維運指示燈 | 不寫偏好；優先序：網址 > 「裝置 → 維運」的開關 > 預設（`?kiosk` 顯示、一般不顯示） |
| `?watchdog=` | `1` `0` | 強制開 / 關渲染看門狗 | 預設：`?kiosk` 與觀眾視窗開、其餘關；`?watchdog=0` 一律關 |
| `?autoupdate=0` | `0`（`false` `off` `no` 同） | 偵測到新版時只記錄、不自動重新載入 | 預設：正式建置有新版且閒置時自動重載；開發版（dev）不做版本檢查 |
| `?reload=HH` | `0`–`23` 的整數 | 每天本地時間 HH:00 之後、閒置時重新載入一次 | 頁面要一直開著才有效；不是 0–23 的值會被忽略；「裝置 → 維運」會顯示 |
| `?tourstop=` | `1`–`8`，或站 id：`reservoir` `tide` `moon` `dust` `air` `birds` `fish` `stations` | 資料載入後直接從那一站開始資料導覽（只啟動一次） | 不合法的值（例如 `zzz`、`9`）不啟動導覽；有這個參數時不顯示新手導覽；「複製此站連結」產生的網址用站 id（有導覽腳本時連結也帶著腳本）；載入了導覽腳本時以「腳本內的站」為準，站不在腳本內就從第 1 站開始 |
| `&tourhold=1` | `1`（`0` `false` `off` `no` 為關） | 配合 `?tourstop=`：到站後停在暫停狀態（導覽員模式） | 沒有 `?tourstop=` 時沒有作用 |
| `?speak=` | `1` `0`（也認 `on` `true` `yes`、`off` `false` `no`） | 導覽的語音旁白預設開 / 關 | 預設關；優先序：網址 > 使用者偏好 > 關；只在主視窗出聲，瀏覽器不支援語音合成時沒有作用；預設開時，第一次觸碰 / 按鍵會先無聲解鎖（iOS 需要）。見〈資料導覽〉 |

## 分享

按 `分享` → 複製一條帶目前海況的網址：

```text
?s=<視覺參數>&o=<海況>&m=<調查月份>&sl=<鳥魚連動>&lang=<語系>
```

除了畫面參數，還包含你選的海況（水庫 / 潮汐 / 揚塵 / 月亮 / 空氣品質）、手動預覽的月份、鳥魚是否連動調查資料，以及介面語言。對方開啟就會看到與你一樣的畫面與資料脈絡（載入順序：海況選項 → 月份 → 鳥魚連動 → 視覺參數 → 語系；視覺參數最後套，不會被海況預設值蓋掉）。

- 展場網址（只帶 `?lang=` 或 `?kiosk=1`）不算分享連結，首次到訪仍以今天真實的海開場。

## 資料導覽

讓不會操作的觀眾也能「看懂」這片海：程式自己一站一站巡演真實資料，並用字幕解釋。導覽員也可以像簡報一樣掌控節奏：跳站、暫停、把某一站的連結傳給別人。

**怎麼開始**：鍵盤 **`T`**；面板「資料導覽」卡片（在資料卡之後）的「▶ 開始導覽」；或閒置 30 秒自動開始（預設開，可在卡片取消勾選「閒置 30 秒自動導覽」，偏好存在瀏覽器；`?kiosk=1` 預設開，`?tour=0` / `?tour=1` 強制關 / 開，優先於偏好與 `?kiosk`）。`?tour=` 的值若是站 id 清單（例如 `?tour=air,fish`）則是載入「導覽腳本」，見下面〈導覽腳本〉。

**八站**（預設的完整導覽；缺資料的站自動略過；AR 實景時略過看不到的月亮與星座站；整輪約 111 秒；用「導覽腳本」只講其中幾站時時間依站數而定）：

| 站 | 內容 |
|---|---|
| 今日水庫 | 水位 % → 海水高度 |
| 花蓮潮汐 | 播放 24h 潮位，字幕帶潮差（大潮 / 小潮…）、農曆與月相 |
| 月亮 | 月亮在天空移動，字幕帶今日月出 / 月沒 |
| 雲林揚塵 | PM10 → 海水濁度；PM10 感測器無效時誠實說明「改看風速」，來源疑似凍結、歷史累積中也會明講；水利署風速凍結（或根本無效）時，改播 Open-Meteo 的逐時**模型風速**，字幕明講「模型資料，非政府觀測」與原因，球播的就是字幕說的那份序列 |
| 空氣品質 | Open-Meteo / CAMS 模型的逐時 PM2.5：PM2.5 越高，海水越混濁、垃圾越多；字幕明講「模型資料，非政府觀測」。**這一站永遠播「字幕描述的模型序列」**，即使環境部觀測存在、資料卡的「驅動海況的資料」選了觀測（資料卡的切換只影響資料卡自己的播放），字幕與球才不會各說各話；有環境部觀測且能對齊出足夠的小時時，說明多一句與環境部測站的比較（「模型平均高估 / 低估 x μg/m³」或「大致吻合」，結論與資料卡同一份說法），下方多一行出處與授權（政府資料開放授權條款－第1版） |
| 鳥群 | 調查年表逐年播放，字幕列出無調查（內插）的空窗年 |
| 魚群 | 同上（例：曾文溪 2007–2013 無調查） |
| 河川測站星座 | 188 座河川流量測站 |

**畫面**：畫布下方的大字幕（標題 1 行 + 說明最多 2 行、淡入淡出；說明較長的站——例如有比較句的空氣品質——放寬為 3 行，手機寬度與橫放矮螢幕上有比較句的可到 6 行〔每行字少，句尾的比較結論才不會被省略號吃掉〕，必要時加一行出處、導覽腳本的備註再加一行），下方是可點的進度點（n/N）與一列導覽員按鈕。字幕只存資料、顯示時才依當下語系翻譯，所以導覽中途切換語言字幕會立刻換。短螢幕橫向（例如手機橫放）時，字幕改成靠左下的窄卡，不蓋住球的下半。屬「播放與參數提示」那一組（`I` 關閉時字幕隱藏，導覽照跑）。

**導覽員控制**（導覽進行中；導覽員按鈕、進度點與「複製連結」都不算「操作海」，不會中止導覽）：

- **進度點**：點任一點跳到那一站，字幕與海況立即套用，導覽繼續、不切換演出模式。
- **按鈕列**：上一站、暫停 / 繼續、下一站、複製此站連結，以及（瀏覽器支援語音合成時才出現的）念出字幕。字幕卡與面板的「資料導覽」卡片各有一組。
- **鍵盤**：`←` 上一站、`→` 下一站、`P` 暫停 / 繼續；`Esc` 仍是結束並還原。
- **暫停語意**：暫停會凍結該站的計時與資料播放（字幕卡邊框變琥珀色並出現「已暫停」標籤，資料 HUD 也顯示「已暫停」，而不是極小的倍速）；暫停中在導覽內跳站，新的一站也維持暫停；繼續時從該站剩下的時間接著走。**暫停中碰任何東西**（點畫面、動旋鈕、按其他鍵）**仍會結束導覽並還原原本的海**，播放倍速也還原。**自動導覽（閒置啟動 / 展場）的暫停有 3 分鐘逾時**：展場上有人按了暫停就走開，導覽不會整個下午定格在同一站——3 分鐘內沒有任何導覽員操作（暫停、上一站 / 下一站、點進度點）就自己繼續；暫停中換站或再按暫停會重新計時。**手動啟動的導覽與導覽員模式（`?tourhold=1`）不逾時**，暫停多久都行，直到你按 `P`、碰任何東西或 `Esc`。自動導覽每輪回到第 1 站時會用當下的資料重建站表，資料更新（每 30 分鐘 / 3 小時）之後字幕的數字才會跟球實際套用的資料一致；手動導覽的站表整輪不變。
- **每站連結**：「複製此站連結」複製 `https://…/?tourstop=<站 id>`（暫停中另帶 `&tourhold=1`，英文介面另帶 `&lang=en`），按鈕短暫變成「已複製」，OUT 監看多一行紀錄。連結只含站 id、語言與暫停旗標，**不會夾帶**目前網址上的其他參數（`?kiosk`、`?audience`、`?s=`、`#remote=` 之類）。別人開啟後，資料載入完成就從那一站開始（只啟動一次）；帶 `tourhold=1` 則停在暫停狀態；這種連結不會先跳出新手導覽擋住。`?tourstop=` 認 `1`–`8` 或站 id（`reservoir` `tide` `moon` `dust` `air` `birds` `fish` `stations`）；不合法的值不啟動導覽；連結的站這次因缺資料或 AR 實景被略過時，從第 1 站開始。連結用站 id 而不是序號，是因為缺資料或 AR 實景會略過某些站，序號會位移。
- **觀眾視窗**：顯示同樣的字幕與進度（含導覽腳本的備註），但進度點不能點、沒有按鈕列；主視窗暫停時顯示「已暫停」並停住進度條。
- **導覽員手機遙控**：講解者用手機當遙控器，站在投影機旁換站、暫停，不必碰筆電。手機的指令與鍵盤 `←` `→` `P` 一樣不算「操作海」、不會中止導覽；見〈多人合奏與導覽員遙控〉。
- **語音與揮手換站**：開啟「裝置」的語音指令後，導覽進行中說「下一站」「上一站」「暫停導覽」「繼續導覽」「結束導覽」（「開始導覽」隨時可用），或開啟相機手勢後對鏡頭揮手（向左＝下一站、向右＝上一站），都不會中止導覽；細節與限制見〈「裝置」面板〉。

**導覽腳本（選用）**：導覽員可以只講其中幾站、換順序，並為每一站寫一句給觀眾看的備註。面板「資料導覽」卡片展開「導覽腳本」：

- **編輯**：勾選要講的站、用「上移 / 下移」排順序（至少 1 站、最多 8 站）；每站可寫一段備註（最多 120 字），顯示在字幕說明下方（較小的暖色字、最多兩行，觀眾視窗也看得到，且備註與出處行會跟著整個字幕隨投影距離放大），開啟旁白時會接在說明後面被念出。備註是你輸入的**原文，不翻譯**（英文介面仍顯示原文；旁白用目前語系的聲音念，所以中文備註配英文聲音可能念得怪），顯示一律當純文字，不會被當成 HTML。導覽進行中編輯區唯讀。
- **儲存**：「套用」立刻生效；「另存新腳本」最多存 5 份（localStorage 的 `ixd2026.tourplan`，只存在這台瀏覽器，不上傳；沒打名字時預設名稱取最小的還沒被用掉的號碼，刪掉「腳本 1」後下一份仍叫「腳本 1」），可切換給不同觀眾；「刪除」要按兩下才會執行；「還原預設」回到完整八站（已存腳本保留）。讀不到 localStorage（隱私模式）時，腳本只在這次有效並會提示。
- **分享**：「複製腳本連結」產生 `?tour=air,fish` 這類網址（有備註 / 名稱時另帶 `&tournotes=` 與 `&tourname=`），對方開啟就是同一份站序與備註，但**不會自動開始導覽**（按 `T`，或再加 `&tourstop=<站 id>` 直接到那一站）。網址有長度上限（約 1800 字元）：備註太長放不進去時，連結**所有備註一併略去**、只帶站序與名稱（編輯器會提示）；存在瀏覽器裡的腳本不受此限。網址腳本只在這次有效，在編輯器套用別的腳本會蓋過它。舊版程式遇到站 id 清單會當成沒指定，不會出錯。
- **範圍**：閒置自動導覽、手動導覽與導覽員導覽都用同一份腳本；腳本裡的站全都沒資料時，閒置導覽退回舊的吸引模式。「複製此站連結」也會帶著腳本。

**語音旁白（選用）**：預設關，開啟前不會要求任何權限。開啟後（按鈕列的「念出字幕」，或網址 `?speak=1` 預設開；優先序：網址 > 偏好 > 關），每換一站就用瀏覽器內建的語音合成（Web Speech `speechSynthesis`）念出該站字幕：中文用 `zh-TW`、英文用 `en-US`，找不到時退到同語系的其他聲音；單位與符號會先口語化（例如「μg/m³」念成「微克每立方公尺」）。

- 只在主視窗出聲，觀眾視窗不出聲；暫停或結束會立刻停止，暫停後繼續、換站、切換語言都會重念目前這一站。該站時間到而句子還沒念完時，最多再等 6 秒才換站；有備註的站（備註接在說明後面一起念）再加備註的預估朗讀時間（字數 × 每字毫秒，加成最多 25 秒），且只在旁白還在念時才續等，念完就換。
- **旁白進行中（含念完後約 0.7 秒），語音指令自動忽略辨識結果**：避免喇叭念出的「鯨魚」「魚群」被麥克風當成指令。
- **iOS 解鎖**：iOS Safari 只允許「使用者手勢的呼叫堆疊內」第一次出聲，所以打開「念出字幕」的那一下點擊會**同步**念一句「旁白已開啟」（英文 “Narration on”）；用 `?speak=1` 預設開時，第一次觸碰 / 按鍵則會無聲解鎖（音量 0 的空白語句），之後導覽才能自動念字幕。解鎖沒成功時最多再試 3 次。**這套解鎖只在假環境測過，沒有在 iOS 真機驗證**（見〈驗證狀態〉）。
- 本站不傳送任何文字；語音由瀏覽器合成，若瀏覽器選到雲端聲音，是否連網由瀏覽器與系統決定。
- 限制：可用的聲音因裝置而異（Windows / Android 可能沒有 `zh-TW` 聲音而退到別的中文聲音，甚至完全沒有；Linux Chromium 常常一個聲音都沒有，此時整段無聲，導覽照常）；iOS Safari 與部分行動瀏覽器要先點過頁面才會出聲，沒點過就靜默不念；英文模式下測站與河川名維持中文原文，英文聲音遇到可能跳過或亂念；缺值的「—」不會被唸成「無資料」。**真實語音合成的聲音與品質尚未實測**（內嵌預覽面板沒有測旁白），見〈驗證狀態〉。

**中斷與還原**：導覽前的參數、海況選項與播放倍速會被記下。碰螢幕、動旋鈕 / 滑桿，或按 `T` `H` `I` `L` `G` `?`、`←` `→` `P`、修飾鍵、`Tab` 以外的任何鍵，導覽立即停止並還原成導覽前的海（`Esc` 或再按 `T` 也可停止）。`L` 與 Footer 的「系統事件」開關、`G`（顯示導覽員 QR）只是切換版面，不算操作海。語言切換、分享、分享星球、錄影、資訊、說明、聲音、匯出 LOG 不算中斷。若你是開始錄製、自己按播放或換海況，則只停導覽、不還原。你暫存的錄製會保留；導覽不會灌水展場角落的「演出 N 次」。

**先還原、再動作**：DOM 事件（點螢幕 / 按鍵）在 capture 階段先中止導覽；非 DOM 的輸入——MIDI 旋鈕與按鈕、語音指令（海的指令）、手機遙控（含走帶鍵）、手把、相機手勢（張手 / 捏合）、滾輪——也一律先呼叫 `activity.touch()`，它的同步掛鉤（`onActivity`）會在動作**之前**中止導覽並還原，所以你的第一個動作（清垃圾、安靜、● 錄製、▶ 播放、旋鈕）落在還原後的海上，不會被 100ms 後的還原蓋掉。分頁被隱藏 / 最小化 / 被完全蓋住時導覽中止並還原（背景時 `requestAnimationFrame` 停了，導覽卻照時間換站、字幕照換，會變成靜止的海配上會動的說明）。只按面板、關彈窗、看資料卡，或播完自己的序列，也算一次活動（30 秒後才會被導覽接手）；自動導覽開始時會收掉開著的資料卡。導覽自己的換站 / 播放 / 溢流不會讓手機或手把震動（你叫出的鯨魚 / 海豚 / 海龜 / 淨化照震）。**導覽員的指令是例外**：導覽員手機遙控的按鈕、語音的導覽指令（「下一站」等）與揮手換站改呼叫 `touchGuide()`——只記一筆「導覽員剛操作過」（讓版本更新 / 每日重載不在這時打斷），**不會**中止導覽；導覽進行中張手也不會讓海面平靜（否則平靜的參數寫入會中止導覽）。

**循環**：手動開始的導覽播完一輪自動結束並還原；閒置自動啟動的會一直循環到有人操作。有彈窗（說明 / 裝置 / 多人）開著時不會自動開始；焦點在導覽腳本編輯器的文字輸入框（備註 / 名稱）、且最近 2 分鐘內有輸入時也先不開始（寫備註停下來想一想不算閒置；超過 2 分鐘沒動就照常自動開始，展場不會被忘在欄位上的焦點永遠擋住）；沒有海況資料時退回舊的色相輪播。

**隱私與權限**：只用已載入的開放資料，不需要任何權限、不上傳任何東西（旁白見上）。觀眾視窗會同步顯示導覽字幕（導覽只在主視窗執行，觀眾視窗不會自己啟動）。

## 多人合奏與導覽員遙控

按頂部「多人」開啟視窗：主畫面成為 host（PeerJS WebRTC，走公共訊號伺服器；短 ID 讓 QR 小而好掃），手機掃 QR 後開啟的是輕量的遙控頁（`#remote=<id>`，不載入 three / 場景 / store）。視窗上方有「合奏 | 導覽員」兩個分頁。

### 合奏（一般遙控）

- 每支手機分到一個聲部（海 / 生態 / 氛圍 / 自由），滑桿每秒與主畫面同步；可啟用手機感測器（傾斜＝洋流方向、搖晃＝浪湧）、動作鈕與打擊墊。全部走同一條 `input()` 路徑，所以可錄製、可 soft-takeover。
- 展場模式（`?kiosk=1`）角落常駐一顆小 QR，並顯示「合奏 N 人」；**導覽員的手機不算在合奏人數裡**。
- **有沒有人在**：展場防呆看的是「手機遙控器最近 3 分鐘有沒有送出操作訊息」（滑桿、動作、打擊墊、導覽員指令），**不看連線數**，所以忘了關的手機不會永遠擋住版本更新（見〈展場防呆與維運〉）。

### 導覽員遙控

講解者用手機當遙控器，站在投影機旁講解，不必碰筆電。

- **怎麼開**：「多人」視窗切到「導覽員」分頁——QR 換成帶 token 的網址（`#remote=<id>&guide=<token>`），下方顯示「等待導覽員手機掃碼 / 已有 N 支導覽員手機連線」與「複製導覽員連結」；切回「合奏」就換回一般 QR。演出模式（`H`）或展場模式下，按 **`G`** 把角落的 QR 換成琥珀色邊框的「導覽員 QR · 僅供講解者」，顯示倒數，**60 秒後自動換回**一般 QR，再按一次 `G` 立即換回（導覽進行中按 `G` 不會中止導覽）。這顆 QR 盒比一般 QR 大（畫布 156px、盒寬上限 174px，英文說明在盒內換行、不撐寬），所以演出模式下字幕會多讓開：視窗 >820px 且高度 >460px 時字幕左右各多預留（合計 400px）、≤820px 時字幕抬高到 216px、矮的橫放螢幕另有規則，避免半透明模糊的字幕蓋住 QR 而掃不到（版面只用 CSS 規則與算術測試守住，**沒有在真實瀏覽器 / 投影機上量過**）。
- **手機上有什麼**：連上並通過驗證後，遙控頁最上方出現「導覽員」區塊——上一站 / 暫停·繼續 / 下一站的大按鈕（按下時輕震 12 毫秒）、開始 / 結束導覽、目前站名（依**手機自己的語系**）、「第 n / N 站」、「已暫停」、該站備註、可點的站名 chips（跳站）、「念出字幕」開關（切換主畫面的旁白偏好，聲音從主畫面出來），以及這一站的細進度條加「剩 n 秒」（暫停時凍結）與「下一站：…」預告（最後一站顯示「最後一站」；手機不知道自動導覽會循環，所以自動循環的最後一站也顯示這句）。主畫面還沒載入海況資料，或正在錄製 / 播放（導覽開不起來）時，「開始導覽」停用並說明原因（後者顯示「等錄製 / 播放結束後才能導覽」；狀態酬載多一個 `busy` 欄位，舊版主畫面沒有它就照舊）。「暫停 / 繼續」是文字會換的動作鈕，不設 `aria-pressed`，目前是否暫停由 `aria-live` 區的「已暫停」念出。原本的滑桿 / 感測器 / 動作 / 打擊墊收進預設收合的「演奏控制」（標示「操作會中止導覽」）；沒帶 token 的一般遙控外觀不變。連到舊版主畫面時，倒數與預告整段不顯示。
- **主畫面端的行為**：導覽員指令只呼叫 `touchGuide()`，**不會中止導覽**；同一連線的同一指令 150 毫秒內重複送出只算一次（連點不會連跳）；導覽沒在跑時只有「開始」與「切換」會啟動導覽；非法的跳站編號被忽略；停止導覽會還原原本的海與播放倍速。

**安全模型**：導覽員權限只有一件事——操控資料導覽，**不能演奏、不能改任何設定**。

- token 是主畫面每個 session 用 `crypto.getRandomValues` 產生的 10 碼隨機英數（沒有安全亂數來源時整個導覽員功能停用，不退回 `Math.random`），只存在記憶體，**只在那一次開啟的主畫面有效**：主畫面重新載入或重建 host（換 ID）之後，ID 與 token 都會換，導覽員必須重掃。
- 手機連上後先送 `hello` 帶 token，由 host 驗證；token 不符或缺少，該連線維持一般遙控（遙控頁會顯示「導覽員連結已失效…先當一般遙控使用」），同一連線驗證失敗 5 次就被關閉。一般連線送來的導覽員指令一律被忽略。
- **QR 外流的風險**：拿到導覽員 QR（例如被拍照）的人，在該主畫面存活期間可以操控導覽（只有導覽）。**沒有全域的失敗次數限制**，也不是一次性配對碼（掃過不會作廢）。所以：只給講解者掃，不要把導覽員 QR 貼在公開處；多人視窗的「導覽員」分頁開著就會一直顯示，講解前請確認台下看不到；用 `G` 顯示的 QR 60 秒後自動換回。
- 一般觀眾的合奏 QR 不含導覽員權限。

**重連與螢幕喚醒**：

- **自動重連**：手機鎖屏、切到背景或換網路後不必重新整理——頁面可見時，連線掉了會依 1、2、4、8、15 秒退避重試（之後一直是 15 秒），狀態列顯示「重新連線中…（第 n 次）」，重連期間所有按鈕停用（不排隊，恢復後要重按）；頁面在背景時暫停重試，回到前景（或網路恢復）立刻重試一次。回到前景時若連線看似開著、4 秒內卻沒收到主畫面的任何訊息，視為死連線並重連。找不到主畫面（`peer-unavailable`，通常是主畫面重新載入了）連續 6 次（約 30 秒）就停止，並提示「主畫面已重新載入，請重新掃描 QR」。
- **同一支手機重連**：同一個 peer id 用新連線取代舊連線時，host 會關掉舊連線，聲部沿用、加入人數不重複計。若 PeerJS 雲端仍認為舊 id 在線而必須改建新 Peer，peer id 會變，主畫面認不出是同一支手機：聲部重新分配、加入人數 +1。
- **螢幕保持喚醒**：只在導覽員模式且已連線時要求 Screen Wake Lock，回到前景會重新取得，連線中止或離開時釋放；顯示「螢幕保持喚醒中」。iOS 16.4 以下、非 https 的網址或瀏覽器不支援時顯示「此瀏覽器無法保持喚醒（請把手機的自動鎖定調長）」。一般遙控不啟用。

**限制與誠實聲明**：

- 需要 WebRTC 直連或 TURN 中繼；場地 Wi-Fi 若擋 P2P（client isolation、擋 UDP），請讓導覽員手機開熱點或與筆電同網段。
- **真實 WebRTC 連線、鎖屏後連線是否存活、自動重連的實際行為、各平台的螢幕喚醒都沒有在真機驗證**（見〈驗證狀態〉）；驗證過的是協定與驗證邏輯（用假連線物件餵給真實的 PeerJS `Peer`）與遙控頁畫面（注入狀態）。
- 「念出字幕」從手機遠端打開時，主畫面瀏覽器是否允許無手勢出聲，取決於那個頁面之前有沒有被點過（見〈資料導覽〉的 iOS 解鎖）；主畫面若從沒被碰過，可能不出聲。
- 導覽員遙控頁的開發輔助 `window.__remoteBoot` 只在開發模式（DEV）存在，正式建置會被移除。

## 點物件看資料出處與觸控筆

**點物件看資料出處**：輕點（位移 < 10 像素、按住 < 0.45 秒、單指、非雙擊的第二下）畫布**背景**上的物件，會在該物件旁彈出資料卡，每張卡片都附資料來源：

| 物件 | 卡片內容 |
|---|---|
| 測站星（188 座河川流量測站的背景星座） | 站名、河川、集水面積、現存或已廢、亮度說明 |
| 月亮 | 今日月出、中天（含仰角）、月沒、現在的方位與仰角、月相（潮汐海況則顯示月相與潮差） |
| 球外鳥群 | 流域、本月鳥種數（缺月標「內插」）、調查年範圍、推算群數 |

點空白處、按 `Esc`、按卡片右上 ×、或 6 秒沒操作會關閉（游標停在卡片上不會自動關）；按 `I` 關閉畫面資訊後不彈卡片；語言切換時卡片文字即時換（站名與河川名維持中文原文）；窄畫布（≤520px）卡片停靠在畫布下緣。
限制：星座或月亮淡出時、AR 實景時不能點；球體範圍內的輕點仍是「亮星爆發」，所以疊在球體範圍內的鳥群不會開卡；在星上快速雙擊時第一下會先開卡，切演出模式後卡片最多再停留 6 秒。觀眾視窗會顯示主視窗的卡片（位置以畫布相對座標鏡像，兩個視窗長寬比不同時圓環與物件可能有些微偏差）。

**觸控筆壓力與傾斜**（僅 `pointerType === 'pen'`：Apple Pencil、Surface Pen、Wacom；滑鼠與手指不會觸發）：

- 壓力：拖曳球體時，壓得越用力，浪勁（轉動慣量與浪湧增量）越大。
- 傾斜：筆按在畫布上時，筆身傾斜推動洋流方向 X / Y（筆立起、傾斜在 6 度內不動；筆懸空不按時不動；更新頻率不超過每秒 20 次）。傾斜是**絕對映射**，而自然握筆本身就會傾斜約 20–45 度，所以用筆時洋流會偏向握筆方向——展場若覺得太敏感，可用 `?pen=0` 關閉。
- iOS Safari 的 Apple Pencil 可能只提供 `altitudeAngle` / `azimuthAngle` 而沒有 `tiltX` / `tiltY`，程式有後備換算（見驗證狀態：尚未在真實 iPad 驗證）。
- 不使用任何權限、不蒐集資料；沒有「裝置」面板的開關。

## 調查空窗時間軸

資料卡的鳥群 / 魚群調查卡有「調查時間軸」：依真實年份等比例畫出每個調查年（小柱高度依物種數），沒有調查的年份畫成琥珀色斜線陰影並標「無調查 2007–2013」（例：曾文溪魚類 2004–2015 共 12 個日曆年，其中 2007–2013 沒有調查）。

- 按「▶ 播放調查年表」逐年推進，每年約 0.7 秒（曾文溪魚類 12 步約 8.4 秒）；空窗年以**前後調查年的線性內插**驅動海況，時間軸上的游標掃過並亮起目前年份，畫布上方的資料提示與 OUT 日誌都明講「無調查（內插）」與整段空窗區間。
- **內插值只是示意，不是觀測資料**；平均 / 基準只用真實調查年。
- 可及性：時間軸有 `role="img"` 與 `aria-label`（例如「調查年度 2004、2005、2006、2014、2015；2007 到 2013 無調查」）；版面全用百分比，≤400px 不會溢出；播放中游標由 `store.subscribe` 直接寫 DOM，不觸發 React 重繪。

## 新手導覽、系統事件監看與視角取景

三個讓第一次使用的人（尤其是手機）更容易上手的功能。

### 新手導覽

- **內容**：第一次進站自動出現，7 個小步驟——歡迎、轉動與觸碰、調整海、接上真實資料、資料導覽、更多功能、準備好了——每步一兩句話，並用聚光外框標出要看的地方（半透明遮罩 + 提示卡，卡片上有進度點、「第 n / 7 步」、上一步 / 下一步 / 略過）。目標在可捲動的面板裡時會先捲進視野，結束後還原原本的捲動位置；目標不存在或看不到時退回置中的卡片。
- **手機**：寬度 ≤ 520px 時提示卡改成貼近畫面下緣的 bottom sheet；目標在畫面下半（控制面板的滑桿、資料卡）時改貼上緣，避免蓋住聚光的目標。
- **操作**：桌面 `→` / `Enter` 下一步、`←` 上一步、`Esc` 略過；手機直接點卡片上的按鈕。導覽開著時焦點留在卡片內（`Tab` 只在按鈕間循環），背景的全域快速鍵不作用。
- **記住**：只有「完成」或「略過」才寫入瀏覽器（localStorage 的 `ixd2026.onboarded`，並與舊的 `ixd2026.seen` 成對寫入）；已經有 `ixd2026.seen` 的舊使用者不會被打擾；讀不到 localStorage（例如隱私模式）視為第一次，每次載入都會出現（同一分頁完成後改由 sessionStorage 記住）。首次到訪仍以今天真實的海開場。不上傳任何東西。
- **何時不出現**：`?onboard=0`；展場模式 `?kiosk`；資料導覽的每站連結 `?tourstop=`（收到連結的人要直接看到那一站）；手機遙控頁、觀眾視窗、診斷頁。`?onboard=1` 可強制顯示（遙控頁、觀眾視窗、診斷頁除外）。
- **重看**：「說明」→「重新看新手導覽」。
- **說明視窗**：長篇說明不再一進站就跳出，收進「說明」鈕（或 `?`）：一句導言 +「快速上手」5 條 + 6 個預設收合的主題區塊（操控方式、MIDI 與聲音、真實資料與導覽、畫面與實景、多人 / 分享與展場、語言與裝置）+「海洋生態」區塊。

### 系統事件監看（輸入輸出監看）

- **隱藏方式**：監看標題列右側的小箭頭、Footer 的「系統事件」開關（手機上顯示短字「事件」）、鍵盤 `L`。
- **預設與記憶**：桌面（寬度 > 820px）預設顯示、手機預設隱藏；你切換過就記住（localStorage 的 `ixd2026.monitor`，值為 `show` / `hide`）。沒有偏好、也沒有網址覆寫時，視窗跨過 820px 會自動跟著顯示 / 隱藏；一旦手動切換，就不再自動跟隨。`?log=1` / `?log=0` 只覆寫這一次、不寫偏好；優先序：網址 > 使用者偏好 > 依寬度預設。
- **隱藏時**：監看與它上方的分隔線都不渲染，畫布與右側面板往下延伸；日誌照常累積，「匯出LOG」與再次顯示都是完整的。Footer 改用一行小字（`aria-live="polite"`，更新有節流）顯示最新一則 OUT 事件。每次切換會在 OUT 日誌留一行「系統事件面板：顯示 / 隱藏」，所以匯出的 LOG 會多這幾行。
- 演出模式（`H` / `?kiosk`）本來就看不到監看與 Footer。桌面 Footer 的高度為配合新開關改為自動（最小 26px、可換行）。

### 視角自動取景

- **為什麼**：相機的垂直視角固定（45°），水平可視範圍等於垂直乘以畫布長寬比；手機直式全螢幕（例如 375×812，長寬比約 0.46）時，球會被左右切掉。
- **做法**：畫布比「球剛好貼滿」還窄時（長寬比約低於 0.95），相機沿原本的視線方向**拉遠**（只拉遠、不拉近）；更寬的畫布（桌面、橫式、接近正方形）倍率恆為 1，取景與過去逐位元相同。依公式計算，手機直式演出模式（375×812、390×844）在預設的「完整」取景下相機距離約 12.9（原本 6.6，約 1.95 倍），平板直式 768×1024 約 1.24 倍。
- **兩種取景（第 5 輪）**：**完整**（預設）以含光暈的視覺半徑取景，整顆球連光暈都在畫面內；**填滿**以球殼半徑取景，球殼剛好填滿較窄的那一邊，直式手機的球更大（375×812：球殼直徑約 374px，完整約 311px；相機距離約 10.75，完整約 12.88），光暈被邊緣裁掉一部分。在「裝置 → 取景」選擇（存成偏好），或用 `?fit=full` / `?fit=fill` 只覆寫這一次；長寬比 ≥ 約 0.95 時兩種都是原本的取景。細節與限制見〈「裝置」面板〉的取景一節。
- **行為**：縮放滑桿與雙指縮放照常可用（預設值一定看得到整顆球；在直式手機上仍可拉近拉遠）；視窗、螢幕方向、面板寬度、取景模式改變時約 0.5–1 秒平滑調整；第一幀直接就位，不會先被切掉再縮回；WebXR 桌面放置時不動；`?fit=0` 關閉（除錯用）。全部在本機計算，不使用任何權限。
- **連帶調整**（只在拉遠時生效，桌面不變）：背景的河川測站星座在直式時改放到球的上方置中，並**避開頂端的資料列**（最高的星離畫布頂端至少 72px，375×812 實測約 70–71px 含極慢的擺動，寬螢幕的版位與改版前逐位元相同）；霧的近 / 遠距離與背景星殼會跟著相機距離放大，否則水體被霧吃掉、星點會貼在鏡頭前變成大光斑。
- **限制**：寬螢幕上球殼在垂直方向約佔畫面 77%（維持現況，沒有為此改變）；直式手機上球的螢幕直徑較小（完整取景下 375 寬約 311px，約桌面 540px 的 58%），點物件選取的半徑是固定的螢幕像素（手指 24px，`src/lib/inspect.js` 的 `THRESHOLD_PX`），沒有跟著縮放，所以直式時星座縮小後點選更容易點到鄰近的星；資料列若換行超過 3 行或有人加高頂端條，星座的保留區（`STATION_HUD_PX`，目前 72px）要跟著調；月亮圓盤在長寬比 < 0.31 的極端窄畫布上邊緣可能被切掉一點點（一般手機最窄約 0.39，不受影響）。

## 「裝置」面板

頂部「裝置」鈕開啟。面板集中放**選用**的裝置功能，每一節有自己的開關與狀態說明；常駐邏輯在 `src/services/*Service.jsx`，不開啟就不會用到相機 / 麥克風，也沒有額外的計算成本。

| 功能 | 預設 | 需要的權限 |
|---|---|---|
| 觀眾視窗（雙螢幕） | 關（按鈕開啟） | Chrome / Edge 自動放到外接螢幕時：「視窗管理」 |
| 相機手勢 | 關（需明確打開）；其中「揮手換站」開關預設開、會記住你的選擇 | 相機 |
| 語音指令 | 關（需按「開始收音」；重新整理後一定是關） | 麥克風 |
| 取景 | **完整**（含光暈；可改「填滿」，偏好存在這台裝置） | 無 |
| 觸覺回饋 | 觸控手機開、桌機關、系統要求「減少動態效果」時關 | 無 |
| 畫質 | **自動**（會依 FPS 自己升降級；可手動鎖定） | 無 |
| 裝置診斷 | 兩個連結（「開啟裝置診斷」與「開啟導引模式」，各開新分頁）+ 上次診斷的摘要 | 無（診斷頁裡的相機 / 麥克風等互動檢查才各自要求權限） |
| 維運 | 一律顯示，不需要開啟；角落指示燈的開關在這裡 | 無 |

> 注意：畫質的預設是「自動選擇」，也就是進站就會量測 FPS 並在畫面卡頓時自動降級（詳見〈畫質〉），不是「預設關閉」。

### 觀眾視窗（雙螢幕）

- **怎麼開**：「裝置」→「觀眾視窗（雙螢幕）」→「開啟觀眾視窗」；「關閉觀眾視窗」會請該視窗自己關閉。面板顯示連線中的觀眾視窗數與偵測到的螢幕數。
- **能做什麼**：筆電操作、投影機給觀眾看。開一個沒有控制介面、不出聲音的視窗（網址 `?audience=1`），全螢幕顯示同一片海，含資料看板、資料播放 HUD、導覽字幕與資料出處卡片。主視窗的參數、資料播放（倍速 / 循環）、鯨魚 / 海豚 / 海龜 / 淨化波、打擊墊效果、語系、資訊面板開關都即時同步；資料卡的「驅動海況的資料」（環境部觀測 / 模型資料）與「裝置 → 取景」（完整 / 填滿）也會鏡像過去：切換後，觀眾視窗資料看板的「驅動」列會跟著變，球會平滑換取景（橫式螢幕兩種取景本來就一樣，只有直式或窄視窗看得出差別；觀眾視窗自己網址的 `?fit=` 優先，也不會反過來改主視窗的取景）。
- **權限與支援**：Chrome / Edge 在 HTTPS 或 localhost 下會詢問「視窗管理」權限（`getScreenDetails`），允許後視窗自動放到外接螢幕，在該視窗點一下即進入全螢幕。**Safari / Firefox、只有一個螢幕、拒絕權限、非安全來源**時退回開一般視窗，請手動拖到投影機畫面再點一下進入全螢幕。首次授權可能讓使用者手勢過期而被彈窗封鎖器擋下，面板會提示「請再按一次」。
- **螢幕不休眠**：觀眾視窗自己持有 Screen Wake Lock（系統層級：投影機與筆電螢幕都不會因為沒人碰鍵盤滑鼠而休眠，導覽跑很久也一樣）；回到前景會重新申請，不支援的瀏覽器靜默略過。
- **畫質**：投影機常是 4K / 高 DPR，是像素負擔最大的畫面，所以觀眾視窗**用自己的 FPS**自動調整畫質（它的畫質不寫共用偏好，不會和主視窗互相覆寫）；主視窗在「裝置 → 畫質」手動選一級時，已開著的觀眾視窗會跟著鎖定同一級（選回自動就改用自己的 FPS）。投影機若被限制在 30 Hz，自動模式會誤判成效能不足而降級——請在主視窗手動選一級。
- **隱私**：資料只在同一個瀏覽器的兩個視窗之間以 BroadcastChannel（`midisea-audience`）傳遞，不上傳；沒有觀眾視窗連著時主視窗不做任何額外工作。
- **限制**：觀眾視窗是「同參數、同事件」的**複本，不是像素級鏡像**——水母 / 魚群位置、垃圾物理、球體自轉與果凍壓凹不同步。兩個視窗必須同源（同一個網址）。同一瀏覽器開兩個控制台分頁時，觀眾視窗鎖定第一個回應的主視窗。主視窗分頁被切到背景時（瀏覽器降頻計時器）觀眾視窗可能短暫顯示「等待主視窗…」，回到前景後自動恢復。手動開啟的分頁（不是腳本開的）可能無法被「關閉觀眾視窗」關掉。

### 相機手勢

- **怎麼開**：「裝置」→「相機手勢」→「啟用相機手勢」。打開之後才會要求相機權限。
- **能做什麼**：用相機看你的手，不必碰螢幕。
  - **張手**：五指張開並停留約 0.5 秒，洋流速度、游動速度與垃圾數量會慢慢平靜下來（朝約 0.15 / 0.3 / 0.1 靠近；放手後不會彈回、其他輸入可立刻接手）。
  - **捏合**：拇指與食指捏在一起，召喚一隻鯨魚（每 3 秒最多一次，捏著不放不會重複）。
  - **揮手換站**（資料導覽進行中）：張開手掌快速橫掃，**向左揮＝下一站、向右揮＝上一站**（像翻頁，以你自己的左右為準；約 1 秒內最多換一站）。只在相機手勢已啟用、且資料導覽進行中才會處理；沒在導覽時揮手完全沒反應。慢慢移動、握拳橫掃、只動手指、來回打招呼式的揮手、從畫面邊緣掃進 / 掃出都不算；一次揮動只換一站，收手動作不會退回。換站走導覽員通道，**不會中止導覽**；導覽進行中且「揮手換站」開著時，**張手不會讓海面平靜**（否則平靜的參數寫入會中止導覽），導覽結束後張手停留約 0.5 秒才恢復平靜；捏合仍照舊，且會中止導覽。在最後一站再揮「下一站」＝一般的「下一站」行為（手動導覽結束並還原；自動導覽回到第一站）。「揮手換站」是獨立的開關（預設開；存在 `ixd2026.wavenav`，重新整理後維持；只有在相機手勢啟用時才有作用），面板會說明目前是待命還是就緒，畫面狀態列與 OUT 日誌會顯示「揮手：下一站 / 上一站」。
  - 其他手勢（握拳、比讚、比耶、手指併攏）一律忽略；手離開鏡頭超過 1 秒回到閒置。分類只用距離比值與夾角，左右手、鏡像前鏡頭、任意旋轉都適用。
- **畫面**：畫布右上角顯示「相機使用中」紅點（**永遠顯示**，不受 `I` 控制）與「手勢 · 偵測到：張手 / 捏合 / —」（跟著資訊面板開關）。
- **權限與隱私**：相機。影像只在這台裝置上處理，**不上傳、不錄下來**；關閉開關、離開頁面或切到背景就立刻停止相機（回到這一頁時自動重新開啟）。AR 實景開著時共用同一個相機串流，否則開一個隱藏的前鏡頭 640×480 `<video>`。
- **需要下載的東西**：第一次啟用會下載手部模型（約 8 MB，來自 Google 儲存空間）與 WebAssembly 運算程式（未壓縮約 11.7 MB，來自 jsDelivr CDN、傳輸時經壓縮；兩者由瀏覽器快取）。MediaPipe（`@mediapipe/tasks-vision`，版本釘死 1.0.1）只在開啟時動態載入，是獨立的 chunk，不進主 bundle。這兩個網路請求會讓 CDN 看到你的 IP，但不會傳送任何影像。Service Worker 不快取跨來源資源，所以**離線的第一次使用會失敗**（面板有明確訊息）。
- **支援與限制**：需要 HTTPS 或 localhost、`getUserMedia`、WebAssembly。偵測約 15 fps、跑在主執行緒（GPU delegate，失敗退回 CPU）；推論慢的裝置（舊手機 / iPad）會量每次推論花的時間並拉長偵測間隔（推論後至少休息 2 倍時間、上限 100ms，主執行緒佔用率壓在約 1/3 ~ 1/2），代價是手勢反應變慢；畫質自動降級不會減少推論成本，也不會暫停它。揮手偵測另外量測「有效幀的間隔」，時間類門檻（統計視窗、冷卻後「幾乎不動」的檢查窗）與單幀跳動上限隨之放寬：幀間隔 ≤ 100 ms 的裝置行為與以前完全一樣，慢推論的裝置（幀間隔約 150–200 ms）也能連續揮手，不再「只能用一次、之後畫面卻一直寫已就緒」（這一點只用合成軌跡測過）。分頁進背景時暫停偵測並放掉自己開的相機。AR 用後鏡頭、手勢用前鏡頭，部分 Android 裝置無法同時開兩個相機。**分類門檻是在合成手部模型上調校的，未用真實相機調過**；**揮手的門檻（0.5 秒內橫向位移約 0.27 個畫面寬、冷卻 1 秒…，集中在 `src/lib/gestures.js` 的 `WAVE`）同樣是用合成的 landmark 軌跡調的，沒有真機驗證**，不同鏡頭視角、距離、光線與低幀率裝置都可能偏難或偏易觸發；左右方向是依「面對鏡頭時你的左邊＝原始影像 x 較大」推導的，後鏡頭 AR 且人站在手機後方時方向可能相反（見〈驗證狀態〉）。

### 語音指令

- **怎麼開**：「裝置」→「語音指令」→「開始收音」，瀏覽器詢問時允許麥克風。
- **指令**：說出「鯨魚、海豚、海龜、大浪、亮星、淨化、清垃圾、安靜、快一點、停」就會觸發對應效果，可連著說多個（例如「鯨魚 大浪」）；同一指令 1.5 秒冷卻。畫布下方短暫顯示「聽到：鯨魚」。英文對應：whale、dolphin、turtle、big wave（wave）、sparkle（star）、purify、clean、quiet（calm）、faster、stop。
  - 「安靜」讓洋流、游速、垃圾一起朝平靜值靠近一段（連說兩次更平靜）；「快一點」讓洋流與游速朝高值移動；「停」停止錄製 / 播放。
  - 中文詞表刻意寬鬆（含常見誤辨與簡體），所以會有誤觸發，例如「進化」也算淨化、「金魚」也算鯨魚、英文單字 wave / star 就會觸發。
- **導覽員指令**（可以動口不動手地講解）：

  | 中文 | 英文 | 效果 |
  |---|---|---|
  | 下一站 | next stop | 換到下一站 |
  | 上一站 | previous stop | 回到上一站 |
  | 暫停導覽（也認「導覽暫停」） | pause tour | 暫停在這一站（可繼續） |
  | 繼續導覽（也認「導覽繼續」） | resume tour | 從這一站接著走 |
  | 開始導覽 | start tour | 開始資料導覽（隨時可用） |
  | 結束導覽（也認「停止導覽」） | stop tour | 結束導覽並還原原本的海 |

  這些指令走導覽員通道，**不會中止導覽**；只有導覽進行中才對換站 / 暫停 / 繼續 / 結束生效，沒在導覽時只會在 IN 日誌寫一行「聽到了、導覽沒在進行」（「開始導覽」才會啟動）。詞表刻意保守：中文一定要有「站」或「導覽」，英文一律是兩個字以上的片語，也不收講解裡常見的「離開導覽區」「取消導覽行程」之類說法；所以單說「暫停」「停止」仍是原本的「停」（停止錄製 / 播放），並且會**中止**導覽並還原。導覽進行中，辨識器逐字串流會先聽到「暫停」才聽到「暫停導覽」，所以這段時間 interim 結果裡的「停」會延後 0.9 秒處理（同一段逐字稿出現導覽指令就取消）——代價是導覽中單說「停止」比以前慢 0.9 秒；沒在導覽時行為完全不變。
  - **限制**：辨識器是逐字串流，講解時自然說到「下一站是水庫」「the next stop」也會被當成指令；展場噪音下也可能把環境聲誤寫成詞表裡的片語。緩解方式只有沿用 1.5 秒冷卻、旁白念字幕時（含餘音約 0.7 秒）不辨識，以及上述保守詞表；想更精準可改成只接受最終結果（代價是多 1–2 秒延遲），目前沒做。
- **辨識語言**跟著介面語言（中文 `zh-TW` / English `en-US`）切換，一次只辨識一種；想說另一種語言請先切換介面語言。
- **權限與隱私**：麥克風。Chrome / Edge 的語音辨識會把麥克風聲音送到雲端服務（Google / Microsoft）辨識，**需要網路**；Safari 依系統設定處理。本站**不錄音、不保存、不上傳音訊**。只有按下「開始收音」才會建立辨識器並要求權限；收音中畫布右上角**永遠顯示**「收音中」徽章（按 ✕ 立即停止）；分頁進背景自動暫停、切回自動接續。與工具列「麥克風」（吹氣＝風）是各自獨立的功能，可同時開（少數手機同時收音時其中一項可能失靈）。
- **支援**：Chrome、Edge、Safari（Web Speech `SpeechRecognition` / `webkitSpeechRecognition`）；**Firefox 不支援**（開關停用並說明）。
- **限制**：Android Chrome 每次重啟辨識可能有系統提示音；iOS Safari 不支援真正的 continuous，會頻繁結束重啟、可能反覆詢問權限；Brave / Electron 常回 network 錯誤（重試 5 次後自動停用）。「中文 + English 同時」交替辨識沒有做。資料導覽的語音旁白進行中（含結束後約 0.7 秒），語音指令會自動忽略辨識結果，避免喇叭念出的「鯨魚」被麥克風當成指令。

### 取景

- **怎麼用**：「裝置」→「取景」選**完整（含光暈）**（預設）或**填滿（球填滿寬度）**。選擇立即生效（相機沿用既有的平滑移動，沒有跳變）並存在這台裝置（localStorage 的 `ixd2026.view`）；面板會顯示目前取景，以及目前的視窗比例下兩種取景有沒有差別。
- **差別**：只有窄畫布（例如手機直式）看得出來；長寬比 ≥ 約 0.95（桌面、橫式）兩種一樣，且與改版前逐位元相同。「填滿」讓球殼剛好填滿畫面寬度：375×812 時球殼直徑約 374px（完整約 311px），相機距離約 10.75（完整約 12.88），光暈被左右邊緣裁掉一部分（依投影計算約 20%）。手機直式時，測站星座會自動排在球的上方、頂端資料列（保留 72px）的下方，不再被蓋住。
- **網址**：`?fit=fill` / `?fit=full`（`?fit=1` 同 `full`）只覆寫這一次、不改偏好；在面板選一個模式才會存成偏好並解除網址覆寫；`?fit=0` 關閉自動取景（除錯用，面板會顯示警示）。優先序：網址 > 偏好 > 預設（完整）。
- **隱私**：偏好只存在這台裝置，不傳送任何資料。
- **限制**：填滿時球殼最外緣幾乎貼齊畫布邊緣、光暈被裁掉的**視覺觀感與雙螢幕鏡像的實際手感沒有人眼確認過**（若覺得太擠，調 `src/lib/cameraFit.js` 的 `FILL_RADIUS` 或加邊距，測試的解析式斷言要同步）。填滿的相機比完整更近，月亮的可視範圍往中間收（長寬比 ≥ 0.33 都在畫面內；更窄約 0.32 以下月亮邊緣會被切一點，與完整模式既有的限制同性質）。直式時星座縮得更小、188 顆星更擠，**點選測站時更容易點到鄰近的星**（點選半徑沒有跟著調）；星座下緣在平板直式或縮放很近時會蓋到球的上半部（星在球後面、透過球殼可見）；資料看板與置中的星座在水平方向會重疊（看板是半透明覆蓋層）。

### 觸覺回饋

- **怎麼開**：「裝置」→「觸覺回饋」：開關、強度（弱 / 中 / 強），「測試觸感」會依序播放鯨魚（長而低）、水滴（短而輕）、淨化波（漸強）、海豚（兩下輕點）、海龜、錄製開始。
- **事件**：鯨魚、海豚、海龜、淨化波、錄製開始 / 停止、播放開始 / 停止、溢流（海水高度 > 97% 時先一串細碎輕震，再以固定節奏滴水，越滿越快）。有冷卻與全域每秒上限，連續快速點鈕不會變成持續嗡嗡。
- **裝置**：手機（Android Chrome 等）用震動馬達（`navigator.vibrate`）；手把用雙震動馬達（Gamepad `vibrationActuator`，dual-rumble，僅 Chrome / Edge；Chrome 需要先按過手把按鍵才偵測得到）。
- **預設**：觸控手機開、桌機關（接手把後可手動開）；系統開啟「減少動態效果」時預設關。iOS Safari 沒有震動 API，會靜默略過，可改用手把。
- **隱私**：設定（開關與強度）只存在這台裝置的 localStorage（`ixd2026.haptics`），不傳送任何資料。
- **限制**：手機遙控頁（掃 QR 的那支手機）不掛載服務，所以遙控手機本身沒有觸覺回饋（導覽員遙控頁的大按鈕例外：按下時自己輕震 12 毫秒）；點擊亮星尚未接觸覺；溢流水滴以固定節奏模擬，不與聲音同步；`navigator.vibrate` 在桌機 Chrome 也存在但沒有馬達，面板的「支援」只代表 API 存在。

### 畫質

- **怎麼用**：「裝置」→「畫質」→ 自動選擇 / 高畫質 / 中畫質 / 低畫質；顯示目前等級、目前 FPS（每秒更新）與上次自動降級的原因。
- **自動模式**（預設）：連續 3 秒平均低於 40 FPS 降一級；連續 8 秒高於 55 FPS 升回一級；換級之間有最短停留（10 秒）與冷卻，升級後又被降回去會加倍升級冷卻，不會來回抖動。拖曳、錄製 / 錄影或分頁在背景時暫停調整。手動選一級就鎖定，不再自動升降。
- **各等級**：

  | 等級 | 解析度上限 | 生物與粒子 | 其他 |
  |---|---|---|---|
  | 高（現況） | 2 倍像素比 | 100% | 全部效果 |
  | 中 | 1.5 倍 | 約 70% | — |
  | 低 | 1 倍 | 約 50% | 關閉流星；背景模糊不套用，背景清澈改用簡化暗化 |

- **隱私**：只量測畫面更新速度；偏好（模式與最後等級，`ixd2026.quality`）只存在這台裝置。自動模式會記住最後的等級，下次載入從該級起跳。`?quality=` 只是本次覆寫，`?fps=1` 顯示 FPS。
- **限制**：量到的是 rAF 節奏而不是 GPU 時間；iOS 低耗電模式或 30Hz 螢幕會把 rAF 限到 30 fps，自動模式會誤判為效能不足而降到低——請手動鎖定等級。降級會讓 canvas 重新配置大小，分享圖 / 錄影的解析度會跟著目前等級（錄影期間不會換級）。

### AR 桌面（WebXR）

- **怎麼開**：只在「瀏覽器有 WebXR 且 `isSessionSupported('immersive-ar')` 為真」的裝置出現（實務上是 Android Chrome + ARCore）。「裝置」→「AR 桌面」→「在桌面上放置」→ 允許相機權限。用鏡頭掃桌面 / 地板，出現準星環後點一下，就把直徑約 28 公分的海洋球放在那裡；走動時球固定不動，可繞著看各個角度。
- **控制**：畫面下方的 DOM overlay 有海水高度 / 洋流速度 / 海水清澈三個滑桿、鯨魚 / 海豚 / 海龜按鈕、「重新放置」與「退出 AR」（走同一條 `input()` 路徑，所以可錄製）。追蹤遺失時會提示「移動手機，找一個平面」。
- **權限與隱私**：相機只在你按下按鈕後才啟用；影像由瀏覽器的 WebXR 處理，本站看不到也不上傳。「實景」開著時這個按鈕會停用（兩者搶相機）。
- **零成本降級**：所有 XR 程式碼都是獨立的 lazy chunk（`xr` / `XrRuntime` / `XrOverlay` 各約 2–3 kB gzip）。沒有 `navigator.xr` 的裝置（iOS Safari、多數桌機）完全不下載，該節也不出現；退出、被系統中斷或發生錯誤都會回到一般 2D 畫面。
- **驗證狀態**：**沒有在真機驗證**（開發環境沒有 XR 裝置，內嵌瀏覽器也不支援）。狀態機與放置數學有 35 項單元測試（假 session）；渲染層以假 XR manager 做過煙霧測試；一般 2D 畫面在真實瀏覽器確認與改動前一致。hit-test 準確度、DOM overlay、加法混合線稿疊在 passthrough 上的可見度與效能都需要實機確認。
- **限制**：只接受水平面（法線 y ≥ 0.75）；沒有使用 XR anchors，ARCore 長時間追蹤修正時球可能微幅漂移；沒有 DOM overlay 的環境（如 Quest Browser 的 immersive-ar）仍可放置，但看不到滑桿與退出鈕。
- **實機驗證步驟**（有 Android 手機的人請照做並回報）：① 用 HTTPS（或 USB 除錯 + `adb reverse tcp:5173 tcp:5173` 開 localhost）；② 「裝置」面板最下方出現「AR 桌面」，iPhone Safari 與沒有 AR 的桌機不會出現；③ 進入後看到相機畫面、無深藍背景與星空，掃桌面出現青色環；④ 點一下放置，繞一圈確認固定不動、粒子大小協調；⑤ 拖 overlay 三個滑桿、點三種生物；⑥ 遮住鏡頭確認追蹤遺失提示與恢復；⑦ 退出後畫面、背景層、背景模糊 / 清澈都正常；⑧ 英文語系重複一次。

## 裝置診斷頁

到現場、或換到一台沒用過的裝置之前，用實際的硬體逐項確認相機、麥克風、語音、MIDI、手把、震動、螢幕、全螢幕……能不能用。它是「真機驗證日」的主要工具（見〈驗證狀態〉）。

- **怎麼開**：網址 `?diagnostics=1`（例如 `https://midisea.shyetech.com/?diagnostics=1`；開發時 `http://localhost:5173/?diagnostics=1`），或「裝置」面板 →「開啟裝置診斷」（開新分頁）；要直接進導引模式用 `?diagnostics=1&guided=1`（面板的「開啟導引模式」）。手機與桌機都能用。它是獨立頁面，不載入 3D 場景與主畫面，頁首有自己的 `EN` / `中文` 切換鈕（切換不必重跑檢查）。頁首的大按鈕「依序帶我做完互動檢查」進入**導引模式**，見下。
- **快速檢查（25 項）**：按「執行所有快速檢查」一鍵跑完，約 3–4 秒；不需要任何權限，也不會啟動相機或麥克風。分四組：
  - **環境資訊**：瀏覽器與平台、螢幕與視窗大小、安全環境（https）、語言與時區、網路狀態、處理器與記憶體、儲存空間估計。
  - **圖形與效能**：WebGL（繪圖器與最大貼圖）、2 秒畫面幀率取樣（平均與最低）。
  - **瀏覽器功能支援**：localStorage 讀寫、BroadcastChannel 往返、Service Worker、Web Share 分享圖片、剪貼簿寫入、全螢幕 API、Screen Wake Lock（請求後立刻釋放）、MediaRecorder 錄影格式。
  - **裝置 API 是否存在**：Web MIDI、Web Bluetooth、WebXR AR（只查支援度，不開 session）、語音辨識、Gamepad、震動、PointerEvent 與觸控點數、`getScreenDetails`。
- **互動檢查（15 項）**：每項要按自己的按鈕才會啟動。相機（預覽 + 實測解析度與 fps）、麥克風（3 秒音量條）、語音辨識（5 秒，顯示辨識文字與語言）、Web MIDI 裝置清單、手把（即時按鍵與搖桿）、手把震動、觸控筆與觸控畫板、手機震動（震完回答有沒有震到）、方向與動作感測器（iPhone 會先詢問權限）、螢幕清單（`getScreenDetails`）、彈出視窗、全螢幕進入與離開，以及三項新的：
  - **語音旁白**：在按下的那一下點擊裡**同步**念一句測試句（依語系；iOS 需要），列出 `zh-TW` / `en-US` 的聲音數與離線聲音數，再問「有聽到嗎？」。
  - **看門狗自我檢查**：取樣 3 秒的動畫幀，回報幀數與最大幀間隔；用真的 `watchdogVerdict` 驗證「正常 / 卡死 / 分頁隱藏」三組合成狀態；顯示「這組網址參數在主畫面會不會啟用看門狗」，並附 `?kiosk=1` / `?watchdog=1` 範例。**它不會讓頁面真的卡死**，所以不能取代實機的卡死復原驗證（仍要在主畫面用 `?watchdog=1` 手動驗）。
  - **相機手勢**：按下才要求相機、才動態載入 MediaPipe，偵測約 8 秒，畫面有鏡像預覽與手部骨架，回報模型載入時間、實際 FPS、最多同時偵測幾隻手與看過的手勢（張手 / 捏合）；第一次要下載約 8 MB 模型與 WebAssembly（離線會直接說明），被拒絕、載入失敗、不支援都會記成對應狀態，結束確實放掉相機並關閉辨識器。

  相機畫面、手機震動、全螢幕等需要人判斷的項目可回答「正常 / 不正常」（「不正常」會把該項變成失敗）；其中震動必須回答才算通過，其餘可不答。
- **導引模式（依序帶我做完互動檢查）**：先自動跑完 25 項快速檢查，再一次帶你做一項互動檢查。流程是**開場**（快速檢查摘要、這台裝置沒有該 API 而自動略過的項目與原因、裝置備註、「開始第 1 項」）→ **一次一張全畫面卡片**（頂部「第 n / N 項」與進度條、大按鈕、即時結果與預覽、需要人判斷時的「正常 / 不正常」、略過、上一項 / 下一項、離開導引）→ **總結**（通過 / 失敗 / 不支援 / 已略過 /（有的話）未完成各幾項，每項可「重測這一項」，可複製報告或下載 JSON）。順序是旁白、看門狗、相機手勢、相機、麥克風、語音辨識、震動、螢幕清單、彈出視窗、全螢幕，之後是 MIDI、手把、手把震動、觸控筆、感測器；裝置沒有該 API 的項目（例如 iPhone 的震動、MIDI、全螢幕）自動略過並記成「不支援」。換項、略過、回答完、離開導引都會立刻停掉當下的探測器，相機、麥克風、語音與計時器隨之釋放。
- **裝置備註（選填）**：可摺疊的欄位——裝置型號、作業系統與版本、瀏覽器與版本、測試人、備註（最多 500 字），讓「真機驗證日」在很多支手機上各跑一輪時分得出哪份報告是哪一支。草稿只存在這台瀏覽器（localStorage 的 `ixd2026.diagnote`），不上傳；「帶入偵測值」只在你按下時才讀取（Chrome 走 `userAgentData`，讀不到就解析 UA 字串），且**只補空白欄位、不覆蓋你已填的**（UA 字串推測出的型號常常只有「iPhone」，蓋掉你填的「iPhone 15 Pro」沒有復原；只有瀏覽器主動提供的 client hints 才會覆寫舊值）；「清除備註」會清空並移除草稿。只有你填了的欄位、且只在你按「複製報告」或「下載 JSON」時才會寫進報告；全部沒填時報告完全沒有這一段，輸出與以前一字不差。
- **結果狀態**：通過 / 失敗 / 不支援 / 待操作 / 略過 / 資訊。徽章同時用文字、顏色與形狀表示，不只靠顏色。
- **報告**：按「複製報告」得到 Markdown 表格（40 列，沒測的標「尚未測」；有填裝置備註時另有一段「裝置備註」）加一段 JSON；剪貼簿被瀏覽器擋下時會改顯示可手動全選的文字框。也可按「下載 JSON」得到 `midisea-diagnostics-YYYYMMDD-HHMMSS.json`。
- **隱私**：所有檢查都在你這台裝置的瀏覽器裡執行，**不上傳任何東西**。報告不含 IP、影像或音訊（不再宣稱「不含個人資料」）；不收相機 / 麥克風 / 螢幕的裝置名稱；**但 Web MIDI 埠名稱與手把的型號字串會照實列出**（判讀有沒有偵測到 KORG 控制器要用；藍牙 / 網路 MIDI 埠與手把有時以擁有者命名，貼出報告前請看一眼）；語音辨識只記字數、不記內容；網址去掉 `#hash`。相機、麥克風與語音只在你按下按鈕後才啟動，按「停止」、離開頁面或分頁被隱藏時全部釋放。注意 Chrome 的語音辨識本身會把聲音送到雲端服務（與〈語音指令〉相同）。「裝置」面板只讀寫一份摘要（`ixd2026.diag`）。**你自己填的「裝置備註」**也會**原樣**進報告（包含你填的測試人姓名）。診斷頁頁首的提示與報告內的隱私聲明現在是同一句、不分有無備註：「不含 IP、影像或音訊；Web MIDI 埠名稱、手把型號字串與裝置備註會照實列出，貼出前請先檢查」（中英文各一句，報告內的聲明跟著介面語系）。貼出報告前請自己看一眼。
- **判讀時請注意**：
  - 摘要的「通過」包含純資訊項目（UA、螢幕、語言…）；離線或非 https 會被判為失敗（這是刻意的展場檢查）；Service Worker 在開發模式（不註冊）顯示「待操作」。
  - 幀率取樣量的是空白診斷頁的 `requestAnimationFrame`，反映螢幕更新率與合成器狀態，**不代表** 3D 場景負載下的 FPS；門檻 45 FPS 是經驗值；分頁在背景時該項會略過或逾時失敗。
  - 有些項目受瀏覽器限制：例如 iPhone 沒有震動、網頁全螢幕與 WebXR，多數功能需要 https。
- **驗證狀態**：診斷邏輯有 106 項單元測試（`diagnostics.test.mjs` 87 + `diagnosticsGuide.test.mjs` 8 + `diagnosticsNote.test.mjs` 11；假物件會檢查 `this` 綁定，故意把原生呼叫改成脫離物件的呼叫後測試會轉紅；診斷頁靜態 import 的傳遞閉包只有 react 與 zustand，MediaPipe 只在按下手勢檢查後才動態載入，也有測試釘住）。在真實瀏覽器（內嵌預覽面板，Chrome 引擎，桌面與手機模擬）：第 4 輪跑過快速檢查（當時 25 項中 19 項通過、1 項失敗〔剪貼簿：權限被內嵌面板拒絕〕、2 項不支援〔Web Share 與 WebXR〕，其餘為待操作或略過）；本輪跑過導引模式從開場、15 張卡片到總結的流程；「裝置」面板的診斷與維運兩節也看過。**各項互動檢查的實際硬體行為（相機、麥克風、語音、語音旁白、相機手勢、震動、全螢幕、螢幕管理）沒有實測**（內嵌面板擋相機與麥克風，動畫幀與語音合成也被節流）；剪貼簿在一般瀏覽器的成功路徑（只驗證了失敗提示）、iOS Safari 各項、Android 真機也都沒有驗證——這些正是真機驗證日要做的事。

## 展場防呆與維運

整天不關機的展場沒有工程師在旁邊，所以畫面出錯、顯示引擎中斷、渲染卡死或有新版時，要能自己復原。邏輯在 `src/ErrorBoundary.jsx`、`src/lib/resilience.js` 與 `src/services/ResilienceService.jsx`；狀態與工具在「裝置 → 維運」。

| 防呆 | 行為 | 什麼時候啟用 |
|---|---|---|
| 錯誤邊界（ErrorBoundary） | 畫面 render 出錯時，換成「發生錯誤，N 秒後自動重新載入」、「立即重新載入」鈕與可展開的錯誤摘要，倒數到 0 自動重載。**退避 5 → 15 → 60 秒**：第 1 次 5 秒；1 分鐘內第 2 次 15 秒、第 3 次起 60 秒。**10 分鐘內累積 5 次即熔斷**：停止快速重載，改顯示「發生錯誤，已停止快速重試」、「約 N 分鐘後會自動再試一次」（只到分鐘，不倒數秒）與「立即重新載入」鈕。**熔斷是半開的（半開復原）**：停手後，從最後一次致命事件起算約 **10 分 30 秒**排一次冷卻重載（讓舊紀錄滑出 10 分鐘視窗，重載後退避重新從 5 秒開始）；再壞就再走一輪，好了就恢復。所以永久壞掉的版本大約每 13 分鐘重載 5 次（4 次快速重載 + 1 次冷卻重載；測試以 3 小時的假時鐘模擬，任何 12.5 分鐘視窗內最多 6 次），不會形成重載風暴。代價是：壞版本修好之前，畫面每約 13 分鐘會重載並閃一下復原畫面。停手期間 WebGL / 看門狗路徑的版本檢查照常，有閒置的新版會立刻重載；畫面錯誤路徑的 ErrorBoundary 會卸載整個 app、沒有版本輪詢，修好的部署由下一次冷卻重載（最久約 10.5 分鐘）或「立即重新載入」帶進來。同一瞬間（200 毫秒內）的多筆致命事件併成一次事故，一次崩潰不會被算成兩次。`window` 的 `error` / `unhandledrejection` 只記錄、不重載 | 一律啟用（包在最外層，主畫面、觀眾視窗、手機遙控頁、診斷頁都有） |
| WebGL 遺失復原 | 顯示引擎（WebGL context）遺失時，畫面上方顯示「顯示引擎暫時中斷，嘗試恢復中…」；**4 秒**內沒恢復就自動重載，有恢復則顯示「顯示引擎已恢復」幾秒後消失。分頁在背景時的遺失不會在背景重載，回到前景再給 4 秒 | 主畫面與觀眾視窗一律啟用 |
| 渲染看門狗 | 分頁可見卻**連續 10 秒沒有任何動畫幀**（`requestAnimationFrame`）時判定卡死，自動重載；需連續 2 次檢查都判定才動作，分頁切到背景時不判定 | 展場模式 `?kiosk`、**觀眾視窗**（投影機整天開著，卡死沒人發現）或 `?watchdog=1`；`?watchdog=0` 一律關；一般模式預設關（避免背景 / 省電情境被誤重載） |
| 版本檢查 | 建置時輸出 `dist/version.json`（`{ id, builtAt }`；id 是**程式碼內容**的雜湊——`src/`、`public/`（不含 `public/data/`）、`index.html`、`package.json` / `package-lock.json`、`vite.config.js`，不含測試（`*.test.*`）、測試專用的輔助檔（`src/lib/tourTestEnv.mjs`，只被測試匯入、不會打包進任何 chunk）與文件；同一份程式碼不論建置幾次 id 都相同，也編進程式），頁面定期以 `fetch('/version.json', { cache: 'no-store' })` 比對，不同就是有新版。**每 3 小時只換 `ocean.json` 的資料部署不會改 id**，所以不會讓任何視窗重載（資料由下一列就地更新）。有新版時，**只在閒置時**（無人操作 ≥ 60 秒，且沒有錄製 / 播放 / 導覽 / 彈窗）自動重新載入；忙碌就每 15 秒再看一次。離線或失敗時靜默略過（service worker 不攔截 `version.json`，離線時不會讀到舊快取而反覆重載） | 正式建置一律檢查：每 10 分鐘（展場 5 分鐘）；開發版（dev）不檢查；`?autoupdate=0` 只記錄、不重載 |
| 資料自動更新 | 定期重抓 `data/ocean.json`；`fetchedAt` 較新時**只換資料，不動你目前選的海況與任何參數**（也保留你在資料卡選的「驅動海況的資料」；閒置時才套用；連動中的鳥 / 魚數量不會因新資料自動重算，要等你下次按「套用」）。套用成功時 OUT 日誌出現「資料已更新」一行 | 主畫面：展場每 30 分鐘、一般每 3 小時（僅頁面可見時）。**觀眾視窗也做**：每 30 分鐘、不限頁面可見，就地換資料、不重載（投影機不會為了純資料的部署掉出全螢幕，也不會與主視窗顯示不同的數值） |
| 每日重載 | 網址加 `?reload=3`，每天本地時間 03:00 之後、閒置時重載一次；重載後重新計算成「明天」，不會連環重載 | `?reload=HH`（0–23） |
| 維運指示燈（OpsLight） | 畫面右下角一顆約 8px 的小燈（12px 的可點範圍，貼著角落），**用形狀加顏色**表示防呆狀態：**綠色實心圓**＝正常；**琥珀色空心圓（中間一點）**＝有新版或新資料在等閒置，或崩潰紀錄近 10 分鐘有事件；**紅色實心三角**＝畫面卡死 / 顯示引擎中斷 / 即將重載 / 已停止快速重試；**灰色虛線圓**＝防呆未啟用（開發版）。滑過、聚焦（鍵盤 Tab）或點一下會顯示一行說明（例如「新版 5115d8… 等待閒置（有人操作中）」），並在工具列看得到時附「開啟維運面板」；按 Esc 可收起（滑過、鍵盤聚焦、點一下釘住三種展開方式都有效；焦點仍留在小燈上，Tab 離開再回來才會再展開），釘住的另外會在點別處或 15 秒後收起。每個狀態都有 `aria-label` / `title`。**只掛在主視窗（筆電螢幕），不掛在觀眾視窗**（投影機的觀眾不該看到）；演出模式（`H`）與 `?hud=0` 時仍會顯示 | 展場模式 `?kiosk` 預設顯示、一般預設關；「裝置 → 維運」的開關存成偏好，`?oplight=1` / `0` 只覆寫這一次 |

**閒置的定義**：無人操作至少 60 秒，且沒有錄製、資料播放、手動導覽或彈窗。**手機遙控器最近 3 分鐘內有送出操作訊息（滑桿、動作、打擊墊、導覽員指令）也算有人在**（展場模式也適用）：只看操作訊息、**不看連線數**，所以沒關的手機不會永遠擋住更新；連線、心跳、狀態同步不算。這個判斷同時延後新版重載與資料就地更新最多 3 分鐘。展場模式（`?kiosk`）或「閒置自動啟動」的導覽本來就是沒人時的常態（自動導覽會無限循環），所以它們進行中不算忙；錄製、彈窗與 60 秒內有人操作仍然算忙。**導覽員操作（`←` `→` `P`、點進度點 / 導覽卡按鈕）也算有人操作**——這些操作刻意不算「操作海」（不會中止導覽），但導覽員正在講解時，60 秒內不會被版本更新或每日重載打斷。**手機的 WebXR 桌面 AR 進行中一律算忙**（重載會直接結束 AR，展場模式也一樣）。**觀眾視窗在全螢幕（投影機）時，新版的重載會延後**到退出全螢幕為止（重載會退出全螢幕，要有人走到投影機前點一下才能回去；資料就地更新不受影響，WebGL 遺失與看門狗這類卡死的重載也照常進行）。

**崩潰紀錄**：環狀保留最近 20 筆（時間、訊息、stack 前 300 字、build id、網址旗標摘要），同一次載入內重複的相同錯誤合併成一筆。新版 / 每日重載也會記一筆資訊性事件，不計入崩潰次數與熔斷（熔斷只算會造成重載的畫面錯誤、WebGL 失效與看門狗）。紀錄只存在這台裝置的 localStorage（`ixd2026.crashes`），**不會上傳**；可在「裝置 → 維運」查看與清除。

**建議的展場設定**：`?kiosk=1&reload=3`（可再加 `&lang=en&hud=0`），主機端另開觀眾視窗到投影機（它預設就有看門狗）。若看門狗在你的環境誤判，加 `?watchdog=0` 關掉。

**驗證狀態（誠實聲明）**：
- 防呆邏輯有 107 項單元測試（假環境、假計時器；含 `this` 綁定回歸；含以假時鐘模擬 3 小時的半開復原、遙控器 3 分鐘窗與指示燈狀態判斷）、6 項 service worker 測試（`scripts/sw.test.mjs`：用 `vm` 載入真實的 `public/sw.js`）與 16 項建置設定測試（其中 2 項 dist 驗證預設略過：版本檔那項要設 `MIDISEA_VERIFY_DIST=1`，英文字典 chunk 那項要設 `MIDISEA_VERIFY_DIST=1` 或 `MIDISEA_DIST_DIR=<建置輸出目錄>`）。
- 在真實瀏覽器（內嵌預覽面板）驗證過：**錯誤邊界**（第 4 輪：人為讓元件丟錯 → 倒數 → 自動重載後恢復）、「裝置 → 維運」面板，以及本輪的**維運指示燈**各層級與形狀（開發版以注入狀態的方式驗；注入用的 `window.__opsStatus` 只存在於開發模式）。
- **沒有**在真實環境驗證：WebGL 遺失復原、渲染看門狗（包含它在真實投影機環境的誤判率；10 秒門檻是經驗值）、資料自動更新、每日重載，**熔斷後半開復原的實際等待與重載**（只有假時鐘的單元測試，沒有真的等 10 分鐘）、**遙控器 3 分鐘窗**（沒有用真實手機遙控器驗證）、**指示燈在真實投影機 / 明亮會場的可見度**（它是角落的一顆小燈，投影機的過掃或鏡像顯示可能把它裁掉，太淡或太顯眼要調 `src/styles/resilience.css` 的 `.res-light`），以及**正式部署後 `dist/version.json` 的版本檢查與自動重新載入**（要上線後才能驗）。
- 新版偵測可能比實際部署晚最多約一個 CDN 快取週期（`/version.json` 會經過 Service Worker 與部署 CDN 的快取）；離線時 Service Worker 可能回舊的 `version.json`，結果只是「已是最新」。

## 瀏覽器 / 裝置支援矩陣

**讀表須知**：本表依各功能實際使用的瀏覽器 API 與其公開的相容性推得。本專案主要在**桌面 Chrome / Edge**（含內嵌瀏覽器面板）開發與驗證，Safari、Firefox、iOS、Android 各欄**沒有逐項實機驗證**，「未驗證」就是字面意思。

**行動裝置備註**

- **iPad / iPhone（所有 iOS 瀏覽器）**：沒有 Web MIDI、Web Bluetooth 與震動 API——請用「多人」掃 QR 把手機當遙控器（WebRTC，不需藍牙）。傾斜 / 搖晃感測首次觸碰會請求權限。導覽旁白要先被使用者手勢解鎖才會出聲（見〈資料導覽〉的 iOS 解鎖）；導覽員遙控頁的螢幕保持喚醒需要 iOS 16.4 以上與 HTTPS；診斷頁的震動、網頁全螢幕與 WebXR 項目會顯示不支援。以上都尚未在 iOS 真機驗證。
- **Android Chrome**：支援手機震動與 Web Bluetooth；AR 實景用後鏡頭、相機手勢用前鏡頭，部分機型無法同時開兩個相機串流，可能讓其中一個失敗。
- **舊手機 / iPad**：相機手勢的推論跑在主執行緒，可能拖慢畫面；建議手動鎖定「低畫質」。

## 語系

介面有**繁體中文**與 **English** 兩個語系。切換：頂部語言鈕（顯示 `EN` / `中文`）；或網址 `?lang=en` / `?lang=zh`。語系決定順序：網址 `?lang=` > 使用者偏好（localStorage `ixd2026.lang`）> 瀏覽器語言（`zh*` 為中文，其餘為英文）。切換語言不用重新整理，資料名稱（水庫、流域、縣市、天氣、農曆、潮差）、日誌、分享文案、新手導覽、導覽字幕、導覽旁白的語言（中文 `zh-TW` / 英文 `en-US`）與語音辨識語言都會跟著換；診斷頁有自己的 `EN` / `中文` 切換鈕，切換不必重跑檢查。測站名與河川名是政府資料的專有名詞，英文版維持原文（英文旁白遇到它們可能跳過或亂念）。

**設計**：以**中文原文當 key**。程式本來就是中文，補譯只要把字面量包進 `t()`；英文放在 `src/i18n/en/*.js`（每個功能一個檔，由 `src/i18n/en-all.js` 以 `import.meta.glob` 自動彙整，新增功能不必改任何共用檔）；找不到英文時退回中文原文（開發模式會在 console 記一次）。

**英文字典是動態載入的**（第 5 輪的架構改變）：字典**不在首載的關鍵路徑上**——手機遙控頁的中文模式**完全不下載**它；主畫面與觀眾視窗的中文使用者，在畫面出來之後、瀏覽器閒置時才**預抓**（見下方「預抓」）；診斷頁不預抓，只有按 EN 時才載入。所以「中文使用者完全不下載英文字典」並不成立，成立的是「首載不下載、遙控頁完全不下載、其餘閒置時預抓」。

- **打包**：`en-all.js` 把所有 `en/*.js` 彙整成一份字典，`vite.config.js` 的 `manualChunks` 把它們歸成**單一 chunk `i18n-en-<hash>.js`**（`vite build` 輸出約 110.0 kB、gzip 約 54.6 kB），只被 `src/i18n/index.js` 的 `loadEnglish()` 動態 `import()`，沒有任何 chunk 靜態依賴它，`index.html` 也不 modulepreload 它。效果（以 `vite build` 輸出為準，本輪結尾建置到暫存目錄的實測）：**入口 chunk 由 144.0 kB（gzip 67.4）降到 36.3 kB（gzip 14.3）**；手機遙控頁中文首載由約 148 kB 降到約 95 kB gzip（當時的量測；之後遙控頁多了重連、喚醒與語言提示，目前以建置輸出加總約 100 kB）。
- **API**：`loadEnglish()`（可重複呼叫；載入中共用同一個 promise、失敗可重試、成功後快取、單次嘗試有 20 秒看門狗）、`isEnglishReady()`、`bootLocale()`、`setLocaleAsync(loc)`、`useLocaleLoading()` / `isLocaleLoading()`、`useLocaleFailed()`、`prefetchEnglish()`。`setLocale()` 仍回傳 `undefined`：字典還沒載入時先載入、載完才切換；等待期間語言鈕有忙碌狀態（`aria-busy`、變暗，並有給螢幕閱讀器的 live 文字「Loading English… / 載入英文中…」）。失敗時維持原語系、console 記一行 `[i18n] 英文字典載入失敗…`，**畫面上也顯示約 6 秒的雙語短暫提示**（英文半句直接寫在程式裡，因為失敗的正是英文字典）：逾時（還在跑、只是太慢）→ 再按一次 EN 會重試；硬失敗 → 再按一次 EN 會先存好偏好、把網址的 `?lang=` 改成 `en`，然後**整頁重新載入**（有些瀏覽器會把失敗的 `import()` 記在模組表裡，同一個網址再 import 不會重新請求；網址若帶著 `?lang=zh`，不改的話重載又會被蓋回中文）。
- **啟動**：偵測到英文（`?lang=en`、存過偏好或瀏覽器語言為英文）時，`main.jsx` 一開頭就呼叫 `bootLocale()`（與路由 chunk 的載入並行），**第一次 render 前等字典就緒，最多 8 秒**——所以不會先看到中文再變英文；逾時或載入失敗就先以中文 render（不白屏），字典之後才到會自動切換並重繪。不變式：瀏覽器裡 `locale === 'en'` 代表字典已載入。觀眾視窗跟隨主視窗切到英文（它不走 `setLocale`）時，有安全網自動補載並重繪。
- **Node（測試）維持完全同步**：沒有載入器，字典用 `registerEn()` 手動註冊，`setLocale('en')` 立刻生效；`scripts/i18n-check.mjs` 直接從磁碟讀 `src/i18n/en/*.js`。
- **離線**：Service Worker 對帶 hash 的靜態資產是 stale-while-revalidate，所以 `i18n-en` 第一次被載入後會被快取，之後離線也能用英文；從沒載入過英文、又沒預抓到就離線按 EN 會失敗（維持中文、console 記一行、畫面有提示）。
- **預抓**：`main.jsx` 在畫面出來之後呼叫 `prefetchEnglish()`（`i18n/loader.js` 的 `prefetchWhenIdle`）：閒置時（`requestIdleCallback`，沒有就 4 秒後的計時器）載入英文字典。目的：按 EN 不再依賴當下的網路（展場 Wi-Fi 閃斷也切得過去），chunk 也經 Service Worker 進快取，離線的 PWA 才切得過去。**不預抓的情況**：手機遙控頁與診斷頁（維持輕量）、省流量模式（`navigator.connection.saveData`）、離線、字典已載入；預抓失敗完全靜默（使用者沒有要求它，不算載入失敗）。代價是主畫面 / 觀眾視窗的中文使用者會在閒置時多下載約 55 kB gzip。預抓與其快取行為**只在 Node 單元測試（假計時器 / 假載入器）驗證，沒有在真實瀏覽器 / 正式站量過**。
- **代價與限制（誠實聲明）**：英文使用者首載多一趟往返——字典要等入口 chunk 執行後才開始請求（位元組總量幾乎相同，遙控頁英文 148.2 → 148.5 kB gzip，但快速網路多約一個 RTT；遙控頁的 PeerJS 也要等 mount 後才開始載入）。靜態 `index.html` 的 `<title>` 與 `<html lang>` 仍是中文，直到字典就緒才改。字典逾時後才到時，已存進 store / 日誌的字串是中文快照，不會回溯翻譯。開發模式沒有 `i18n-en` chunk（`import.meta.glob` 的 eager 匯入展開成約 30 個請求）。語言鈕在字典載入期間的忙碌狀態與失敗提示（主畫面、遙控頁、診斷頁）只驗證了元件的伺服器端渲染、原始碼接線與狀態邏輯，沒有用真實的慢網路看過。**正式站在慢網路 / 離線 / Service Worker 下的行為沒有驗證**。
- **新規則**：不要在**模組頂層**呼叫 `t()` / `translate()`（import 當下執行）——路由 chunk 可能比字典先執行完而固定成中文；靜態表用 `T()` 標記、顯示時再 `t()`。`src/i18n/i18n.test.mjs` 以 AST 掃描整個 `src` 守住這一條。另外，`src/i18n/data-tables.js` 是 `src/i18n/en/data.js` 詞素表（天氣與農曆）的副本（`data.js` 不能再靜態 import `./en/`，否則字典會變成主畫面的靜態依賴），測試會逐項核對兩份一致。

**如何新增翻譯**：

1. 把中文字面量包起來：
   - React 元件：`const t = useT()` → `t('分享')`（語系切換時自動重繪）
   - 非 React（純函式、store 日誌）：`import { t } from '.../i18n/index.js'` → 用「當下」語系
   - 靜態表（例如參數登錄表的 `label`）：用 `T('海水高度')` **標記**（原樣回傳中文），顯示時再 `t(label)`
   - 插值：`t('{n} 站', { n: 3 })`；英文值可以是函式 `({ n }) => …` 處理單複數
2. 在 `src/i18n/en/<你的功能>.js` 加一筆 `'中文原文': 'English'`。用語請照 `src/i18n/GLOSSARY.md`（例如全站統一用 sphere，不混用 globe；「分享星球」的按鈕是 Snapshot）。
3. 驗收：`npm run i18n`（等於 `node scripts/i18n-report.mjs`）必須是「未包 t() 的中文字面量 0、缺英文的 key 0、字典重複 key 0」；`npm test` 的 `src/i18n/i18n.test.mjs` 同樣會擋，並額外檢查英文值不含中文、`{placeholder}` 與中文 key 一致。掃描器以 Babel AST 找字面量：註解、`console.*` 與 regex 不算。

**注意事項**：

- 元件若呼叫「讀當下語系的純函式」（`describeBoard`、`formatHud`、`buildTour`…），必須自己 `useT()` / `useLocale()` 訂閱語系，否則切換語言不會重繪。
- 存進 store / 日誌的字串是「當下語系」的快照；要能跟著切換的內容，請存 `{ key, params }`，顯示時再 `t()`（導覽字幕就是這樣做的）。
- 常駐服務若持有和語言有關的狀態（語音辨識的 lang、逐字快取），要監聽 `useLocaleStore.subscribe` 並重設。
- 資料層名稱走 `src/i18n/data.js`（純函式）與 `src/i18n/en/data.js`。
- **說明視窗正文**（`src/ui/info/InfoZh.jsx` / `InfoEn.jsx`）含行內標記（`<b>`、`<code>`），不逐句 `t()`，而是成對維護：兩份的條目順序與事實必須一致；`InfoZh.jsx` 在 `scripts/i18n-check.mjs` 的 `ALLOW_FILES` 內可直接寫中文，**`InfoEn.jsx` 不得含任何中文字元**（i18n 測試會擋）。結構是「快速上手 `QUICK`（最多 5 條）+ 依主題分組的可摺疊區塊 `GROUPS` + 海洋生態」：新增玩法要在兩份的 `PLAY` 陣列各加一筆 `{ id, body }`，並把它的 id 放進 `GROUPS` 裡某一組（每個 id 只能在一組）。`src/lib/onboarding.test.mjs` 會用原始碼解析檢查兩份的 id、分組與行內標記數量一一對應，並釘住目前的條數（19 條玩法 + 5 條快速上手），所以新增玩法時也要一併更新那個測試。說明視窗要保持精簡：只在相關的收合區塊裡補一兩行。

- **空氣品質（模型資料）**：來源是 Open-Meteo Air Quality API 的 CAMS 全球大氣模型（分析 + 預報），**不是政府測站量到的數字**。網格很粗（數十公里），與地面測站（例如環境部麥寮站）可能有落差（有環境部觀測時，資料卡會把兩者並列比較，見下），所以只作示意映射，**不可當官方空品判讀**；資料卡、資料看板、日誌與導覽字幕一律標示「模型資料」。`US AQI` 是美國 EPA 指標，不是環境部 AQI，畫面上一律寫「US AQI」。逐時資料，CI 每次以「過去 5 天」覆蓋抓取，與舊資料依時間合併去重，丟掉預報的未來小時，只留「現在以前」最近 120 筆；抓取失敗保留舊資料。洋流不會隨逐時播放變化（空氣品質的播放只用 PM2.5 驅動，洋流取自今日海況的風速）。授權 CC BY 4.0，需標示「Weather data by Open-Meteo.com」並連回 <https://open-meteo.com/>（資料卡有標示與連結，`ocean.json` 的 `air.note` 也寫明歸屬）。Open-Meteo 的免費 API 限非商業使用，若日後商用需改用付費方案。

  - **誠實聲明（管線）**：管線只用「真實欄位格式的合成 fixture」測過，**沒有用真實金鑰驗證**。欄位名稱、分頁與排序行為依環境部公開說明與 OpenAPI 文件（只列 `language` / `offset` / `limit` / `api_key`，沒有篩選條件）推得；`sort` / `format` 是文件外的常見參數，被拒絕時會去掉重試。**第一次有金鑰時，請看 CI 日誌確認欄位與分頁行為**。環境部 OpenAPI 文件裡的預設範例金鑰是來源不明的公用示範值，本專案完全沒有使用。
  - **誠實聲明（比較）**：模型是數十公里的粗網格（PM2.5 是格點平均），測站是一個點、離格點還有一小段距離；歷史資料集的時間戳定義（整點起訖）與 Open-Meteo 可能差一小時；歷史分頁最多 14 頁，若 API 忽略排序而資料由舊到新，最新的小時可能翻不到，此時只剩目前值 1 筆（日誌會說明）。所以「模型平均高估 / 低估 x μg/m³」與「大致吻合」只是**描述性統計**，落差不全是模型的誤差。判讀規則（資料卡、導覽字幕、遙控頁共用同一份說法）：至少要有 3 個「兩邊都有值」的小時才比較；平均偏差 |bias| < 1 且逐時平均絕對誤差 ≤ 5 μg/m³ 才說「大致吻合」，偏差小但逐時誤差大時說「平均差僅 x，但逐時落差明顯」，避免高低相消造成假象。
  - **標示**：環境部觀測一律標「環境部觀測」並附授權（政府資料開放授權條款－第1版），環境部的 AQI 與模型的 US AQI 分開標示；模型序列一律標「模型資料，非政府觀測」，不會出現「觀測」字樣。導覽的空氣品質站永遠播模型序列（見〈資料導覽〉）。
- **模型風速補洞（揚塵）**：`air.history` 每列另帶 Open-Meteo 的逐時模型風速與風向（`wind`、`windDir`，用獨立請求抓取，失敗只保留舊值、不影響 PM 序列）。水利署 IoW 揚塵的風速無效或凍結時，揚塵歷史改用這份**模型風速**驅動洋流與海水混濁，資料卡、資料看板、HUD 與導覽字幕都明講「風速為模型資料（Open-Meteo），水利署感測器凍結」，不當成政府資料。
- **測站**：只有站點目錄（沒有流量時間序列）；TWD97 二度分帶座標換算成相對座標，僅用於背景星座。
- **月出月沒**：API 預設只回一小段，要帶 `timeFrom` / `timeTo` 才回其他範圍（單次最多 180 天；目前公開 2025-01-01 → 2027-12-31）。CI 取「今日前 2 日起 180 天」的滾動視窗，抓取失敗則保留舊窗口；畫面以 `from / to` 判斷是否涵蓋今日，不涵蓋時閒置的月亮退回天文公式。方位角以正北 0°、順時針；每個陰曆月各有一天沒有月出或月沒。
- **魚 / 鳥調查**：多數流域只有 4–5 個有效月份 / 年度，缺月以相鄰月份環狀內插（標註「內插」）；每月只涵蓋 1–3 個年度，近似單一年份快照，非氣候平均。花蓮溪鳥類 2017–2019 的數量欄位全空（年表的隻次為空）。物種名已正規化（字面 "NULL"、別名順序）。**調查年表是逐年稠密序列**：從第一個到最後一個調查年，每個日曆年一點；沒有調查的空窗年以前後調查年線性內插並標「無調查（內插）」，僅為示意、不是觀測資料，平均 / 基準只用真實調查年。
- 水利署 opendata 在**並行**請求時約 1/4 會回錯置 / 空白 / 截斷的內容，腳本一律依序抓並重試；GitHub runner 連 WRA / CWA 的成功率尚未在 Actions 實測，任何資料集失敗都只會保留舊資料、不影響其他資料集。

## 技術

React + Vite · Three.js + React Three Fiber · Zustand · Web MIDI API · Tone.js · cannon-es · PeerJS（WebRTC）· MediaPipe Tasks Vision（相機手勢，動態載入）· Web Speech API（語音指令辨識、導覽旁白的語音合成）· BroadcastChannel（觀眾視窗）。

**效能設計**：3D 場景在 render loop 內以 `useStore.getState()` 讀參數，MIDI 高頻訊息不觸發 React re-render；錄製緩衝與 soft-takeover 狀態放模組層，避免每則訊息重繪。手機遙控頁與觀眾視窗各自只載入需要的程式碼（遙控頁只依賴 react、PeerJS 與少量共用程式，不含 three / 場景 / store；中文首載依 `vite build` 輸出加總約 100 KB gzip——入口 14.3 + react 48.4 + 遙控頁 6.8 + 共用 guide 5.4 + PeerJS 24.3 + 語言提示 0.5；英文再多一個約 55 KB gzip 的字典 chunk，見〈語系〉（遙控頁的中文模式不預抓它）；這是建置輸出的加總，不是真實網路的量測；主畫面與觀眾視窗一開始就預載 3D 場景）；MediaPipe 只在使用者打開相機手勢（或診斷頁的手勢檢查）時才載入；沒有觀眾視窗連著、沒有開啟手勢 / 語音時，對應的服務不做任何工作。

**入口檔預算**：入口 chunk 目標 gzip ≤ 40 kB，目前 minified 36.3 kB、gzip 14.3 kB（以 `npm run build` 的輸出為準）。這個數字靠英文字典動態載入達成（字典不在首載的關鍵路徑上；主畫面 / 觀眾視窗的閒置預抓發生在畫面出來之後，不計入入口），**沒有自動化測試強制它**（`scripts/vite-config.test.mjs` 只驗證分塊結構：入口不拉 three、字典是單一 `i18n-en` chunk 且只被動態 import），要留意日後有人把大模組靜態 import 進入口。目前入口 chunk 裡最大的是 `resilience.js`（約一半，gzip 約 7 kB）與 `ErrorBoundary`，因為已遠低於預算，沒有拆成動態載入。

**開發輔助**：dev 模式下主控台可用 `window.__store` 驅動測試；`window.__remoteBoot`（遙控頁的連線 / 導覽狀態，預覽面板擋 WebRTC 時用來注入狀態驗畫面）與 `window.__opsStatus`（維運狀態，用來模擬指示燈各層級）**只在開發模式（DEV）存在**，正式建置會被移除。

## 資料 / 授權

政府資料開放授權條款第 1 版 (OGDL v1)。完整資料來源與 schema 見 [SPEC.md](./SPEC.md)。

**Open-Meteo（CC BY 4.0，需標示出處）**：「空氣品質」資料與氣象備援來自 [Open-Meteo](https://open-meteo.com/)，以 CC BY 4.0 授權；使用時須標示「Weather data by Open-Meteo.com」並連結到 <https://open-meteo.com/>——資料卡的空氣品質區塊已附這行標示，連結指向 Open-Meteo 空氣品質 API 的文件頁（`https://open-meteo.com/en/docs/air-quality-api`，來自 `ocean.json` 的 `air.sourceUrl`），`air.note` 也寫明歸屬。空氣品質是 CAMS 全球大氣模型資料，**不是政府觀測值**，也不適用 OGDL v1。Open-Meteo 的免費 API 限非商業使用；本專案只由 CI 每 3 小時抓一次（瀏覽器不直接呼叫），若日後商用需改用付費方案。

**環境部觀測（選用）**：有你自己的金鑰時，「空氣品質」可並列環境部測站觀測，授權為**政府資料開放授權條款－第1版**（`ocean.json` 的 `air.obs` 帶 `license` 與 `sourceUrl`，資料卡標示出處與授權）。它與 Open-Meteo 模型資料是兩份不同來源、不同授權，畫面上分開標示；設定步驟見下面〈啟用環境部觀測〉。

**資料管線**：`public/data/ocean.json` 為建置時快照（水利署水庫水情 + 24h 進流量時序 + 氣象 + 河川水位 + 鳥 / 魚調查 + 揚塵 + 測站目錄 + 月出月沒 + Open-Meteo 空氣品質模型資料與模型風速 + 選用的環境部測站觀測），GitHub Actions 每 3 小時（另在台北 00:10 跨日後）排程 `scripts/fetch-ocean-data.mjs` 刷新並自動 commit，**刷新後主動派發 deploy 工作流程**（GitHub 的設計是 `GITHUB_TOKEN` 的 push 不會觸發其他 workflow）。歷史靜態資料（測站目錄 / 魚類調查 / 鳥類逐年）由 `scripts/bake-static-data.mjs` 一次性烘焙，CI 原樣保留。
- **潮汐 series 每日自動更新，不需要金鑰**：抓 CWA F-A0021-001「潮汐預報」公開檔（未來一個月、266 個地點），取花蓮市乾滿潮事件（海圖基準）做餘弦插值成當日 24h 潮位；併入上次保存的前一日尾端事件，頭段曲線才精準（首次以相鄰半週期鏡射補頭）。有 `CWA_KEY` 時改走官方 datastore API（同一份資料）；兩者都失敗則保留舊 series。
- **空氣品質的模型資料不需要金鑰**：`scripts/fetch-ocean-data.mjs` 每次刷新以 `past_days=5` 抓 Open-Meteo 的逐時資料（PM2.5 / PM10 / US AQI），與舊資料合併去重、只留最近 120 小時；另以獨立請求抓逐時模型風速與風向併進 `air.history`（失敗只保留舊值）；抓取失敗只保留舊資料。**環境部測站觀測**則需要你自己的金鑰，沒設定時整段略過（見下面〈啟用環境部觀測〉）。
- 在 repo **Settings → Secrets and variables → Actions** 加入 `CWA_KEY`（[中央氣象署開放資料平臺](https://opendata.cwa.gov.tw/)申請的授權碼）→ 氣象也改抓 CWA 觀測站（政府源）；未設定時氣象自動退回 Open-Meteo。

**隱私總覽**：網站沒有後端、沒有帳號，程式碼中沒有任何分析追蹤（沒有 Google Analytics 一類的腳本）。相機影像、麥克風聲音都不會被本站錄下或上傳（語音辨識在 Chrome / Edge 是由瀏覽器把聲音送到雲端服務，見〈語音指令〉）；偏好與錄製只存在你自己瀏覽器的 localStorage / sessionStorage。相機手勢第一次啟用會向 jsDelivr 與 Google 儲存空間下載模型與運算程式（只有下載，沒有上傳）。「多人」合奏使用 PeerJS 的公共訊號伺服器建立 WebRTC 連線，連線受 NAT 或會場 Wi-Fi 擋住時會經公共 TURN 中繼（`openrelay.metered.ca`，見 `src/lib/ice.js`）；經過的只有滑桿數值與觸發事件，不含影像或聲音。

**第 4 輪新增功能的隱私**：裝置診斷頁的所有檢查都在你的瀏覽器裡執行、報告只在你按「複製」或「下載」時產生，且不含 IP、影像或音訊（不宣稱「不含個人資料」），也不收相機 / 麥克風 / 螢幕的名稱；但 Web MIDI 埠名稱、手把型號字串與你填的裝置備註會照實列出（判讀有沒有偵測到控制器用，貼出報告前請看一眼）；崩潰紀錄只存在這台裝置的 localStorage（`ixd2026.crashes`），不會上傳；新手導覽、系統事件監看與視角取景只在本機記一個偏好或做計算；導覽旁白由瀏覽器的語音合成負責，本站不傳送任何文字（瀏覽器若選用雲端聲音，是否連網由瀏覽器與系統決定）。版本檢查與資料自動更新只向本站自己的 `version.json` 與 `data/ocean.json` 發出請求。

**第 5 輪新增功能的隱私**：導覽員遙控只經過 WebRTC 傳導覽指令與導覽狀態（站 id 與你輸入的備註，不含影像或聲音）；導覽員 token 只存在主畫面的記憶體，不寫入任何儲存；導覽腳本與備註只存在這台瀏覽器的 localStorage（`ixd2026.tourplan`）或你複製出去的連結裡，本站不上傳（連結裡的備註是明文，別放不想讓拿到連結的人看到的內容）。診斷頁的「裝置備註」草稿只存在這台瀏覽器（`ixd2026.diagnote`），只有你填的欄位、只在你按複製 / 下載時進報告，會**原樣**包含你填的內容（含測試人姓名；報告的隱私聲明因此不寫「不含個人資料」，而是提醒貼出前先檢查）。取景（`ixd2026.view`）、維運指示燈（`ixd2026.oplight`）、揮手換站（`ixd2026.wavenav`）只在本機記一個偏好。語音導覽指令沿用語音辨識的隱私（Chrome / Edge 由瀏覽器把聲音送到雲端服務）；揮手換站沿用相機手勢的隱私（影像只在本機處理，不上傳）。英文字典是本站自己的靜態檔：按 EN 時向本站請求；主畫面與觀眾視窗的中文使用者還會在畫面出來後、閒置時預先向本站請求一次（手機遙控頁與診斷頁不會；省流量模式與離線時也不會）。環境部金鑰只存在 GitHub 的 Secret 與 CI 的環境變數，前端完全接觸不到；瀏覽器只讀 `data/ocean.json`。

### 啟用環境部觀測（選用，需要你自己的金鑰）

環境部的空氣品質 API 需要**你自己申請**的 API 金鑰；本專案沒有代為申請，也不會把金鑰放進程式。管線**只從環境變數 `MOENV_KEY` 讀取**（CI 為 GitHub Actions 的 Secret；`.github/workflows/refresh-data.yml` 已加上 `MOENV_KEY: ${{ secrets.MOENV_KEY }}`）。**沒有設定時完全略過、不影響現況**——沒設 secret 時 workflow 傳進來的是空字串，腳本視為未設定，只印一行「MOENV_KEY 未設定，略過環境部觀測」。

步驟（依環境部公開平台的操作流程整理，**介面名稱可能與實際略有出入**，請以平台當下的畫面為準）：

1. 到環境部資料開放平台 <https://data.moenv.gov.tw/> 註冊 / 登入。
2. 在「會員專區」取得 API 金鑰。
3. 到 GitHub repo → **Settings → Secrets and variables → Actions → New repository secret**，名稱填 `MOENV_KEY`，值貼上你的金鑰。**金鑰只貼在這個 secret 欄位，不要寫進任何檔案、issue 或 commit。**
4. 到 **Actions** 手動執行「Refresh ocean data」（`refresh-data.yml`，Run workflow），看日誌有沒有出現 `moenv station` 與 `air obs refreshed` 兩行。失敗時日誌是 `moenv obs failed`，管線會保留最近 48 小時內的舊觀測（更舊的移除；「48 小時」看的是舊觀測最新的有效 PM2.5 小時與 `fetchedAt`），其他資料集不受影響；若日誌的原因寫「stale」，代表抓到的最新 PM2.5 小時已超過 12 小時（測站可能停測中），不是金鑰或網路問題。

**誠實聲明**：管線**只用「真實欄位格式的合成 fixture」測過，沒有用真實金鑰驗證**；第一次有金鑰時，請看 CI 日誌確認欄位與分頁行為（欄位名稱、分頁與排序依環境部公開說明與 OpenAPI 文件推得，見〈資料集 → 畫面〉）。模型格點是數十公里的粗網格、測站是一個點，兩者的比較只是**描述性統計**，不代表模型好壞。金鑰不會進程式、日誌或 `ocean.json`（所有日誌與例外都遮蔽 `api_key`）。
